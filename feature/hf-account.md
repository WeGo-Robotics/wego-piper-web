# HuggingFace 계정 관리 — 기획

> 상태: **1·2·4 구현됨** (설정 → 저장소 탭, repo_id 고르기, 학습 시작 전 검사). 3 은 아직.
> 조사일 2026-09-01. 아래 "지금 이런 상태다" 는 전부 실측이다.

## 왜 지금인가

**컨테이너 배포에는 HF 로그인 경로가 아예 없다.** 실측:

| | 이 개발 머신 | 컨테이너 배포 (고객이 받는 것) |
|---|---|---|
| 게이트웨이 | systemd 유닛, 저장소에서 직접 실행 | 컨테이너 |
| `HF_HOME` | 호스트 기본 (`~/.cache/huggingface`) | `/data/hf` (= 호스트 `/srv/piper-data/hf`) |
| 토큰 파일 | `~/.cache/huggingface/token` **있음** (37바이트) | `/srv/piper-data/hf/token` **없음** |

즉 **개발 머신에서는 되는데 고객 머신에서는 안 된다.** 그리고 그 차이가 화면
어디에도 안 보인다 — 대시보드에서 옮긴 배지가 "미로그인" 이라고 말할 뿐,
어떻게 로그인하는지는 아무 데도 없다.

⚠ 호스트에서 `huggingface-cli login` 을 해도 **컨테이너는 못 본다.** 토큰이
`~/.cache/huggingface/token` 에 써지는데 컨테이너의 `HF_HOME` 은 `/data/hf` 다.
이걸 모르면 "로그인했는데 왜 안 되지" 로 한참 헤맨다.

## 로그인이 없으면 막히는 것

조사해 보니 HF 인증은 **네 곳**에서 쓰인다.

| 기능 | 없으면 | 파일 |
|---|---|---|
| 데이터셋 업로드 | 녹화한 것을 Hub 로 못 보낸다 | `routers/datasets.py:310` |
| 학습 결과 푸시 | `--policy.repo_id` 를 쓰면 **학습 끝에** 실패한다 | `cli_mapping.py:398` |
| 비공개 모델·데이터셋 내려받기 | 공개만 된다 | `services/hub_client.py` |
| 녹화 repo_id 도움말 | `네임스페이스/이름` 의 예시를 못 보여준다 | `RecordingPage.tsx:230` |

⚠ **두 번째가 가장 비싸다.** 업로드가 학습 **마지막**에 일어나므로, 토큰이 없으면
몇 시간 돌린 뒤 그 단계에서 실패한다. 체크포인트는 디스크에 남지만 화면에는
실패로 뜬다.

## 이미 있는데 안 쓰는 것

`GET /api/hub/whoami` 가 이미 이만큼 준다:

```json
{"logged_in": true, "username": "wego-hansu", "fullname": "...",
 "avatar_url": "...", "orgs": ["..."], "token_name": "..."}
```

**`orgs` 를 아무도 안 쓴다.** 그런데 `repo_id` 는 `네임스페이스/이름` 형식이고,
그 네임스페이스가 바로 개인 계정 또는 조직이다 — 사용자가 직접 타이핑하고 있다.

## 넣을 것 — 우선순위

항목을 지어내지 않고 **위에서 실제로 막히는 것**에서 골랐다.

### 1. 설정에서 로그인·로그아웃 (필수)

토큰을 붙여넣으면 검증하고 저장한다. 지금은 이게 없어서 컨테이너 배포가
영영 미로그인이다.

- `POST /api/hub/login {token}` → `whoami` 로 검증 → **성공했을 때만** 저장
- `POST /api/hub/logout` → 토큰 파일 삭제
- 저장 위치는 `HF_HOME/token` — 컨테이너면 `/data/hf/token` 이라 **마운트로 남는다**
  (재설치해도 유지된다. `/srv/piper-data` 는 지우지 않는 세 경로 중 하나다)

⚠ **토큰을 화면에 되돌려 보내지 않는다.** 저장 여부와 `token_name` 만 보여준다.
한 번 넣은 값을 다시 읽을 수 있게 하면 그 화면이 자격증명 유출 경로가 된다.

⚠ **권한을 확인해서 말해 준다.** `write` 권한이 없는 토큰으로도 `whoami` 는
성공한다 — 그러면 "로그인됨" 으로 보이는데 업로드에서만 실패한다. 학습 끝에
그걸 만나는 것이 최악이다. `whoami` 응답의 `auth.accessToken.role` 을 읽어
읽기 전용이면 그렇다고 적는다.

### 2. `repo_id` 를 고르게 (효과 대비 싸다)

지금은 `wego-hansu/bolt_single` 을 손으로 친다. `orgs` 가 이미 오므로
**네임스페이스는 드롭다운**으로 바꿀 수 있다.

- 녹화 화면, 학습 화면(`policy.repo_id`), 데이터셋 업로드 세 곳이 같은 규칙을 쓴다
- 오타가 사라진다. 지금은 잘못 치면 **녹화 시작에서** 죽는다(`RecordingPage.tsx:224`)

### 3. 대시보드에 "업로드 준비됨" 한 줄 — **구현됨 (2026-09-02)**

> 대시보드에 HuggingFace **별도 카드**(아바타·계정명·토큰 이름·권한 — 토큰 값은
> 안 보낸다). 미로그인·읽기전용이면 요약 줄에도 뜬다. `whoami` 가 `token_role` 을
> 내리게 됐고 `to_thread` 로 뺐다.

대시보드는 "지금 괜찮은가" 에 답하는 자리다. HF 미로그인은 **녹화·학습을 시작할
수는 있는데 결과를 못 보내는** 상태이므로, 시작 전에 알아야 한다.

- 로그인 안 됨 → 요약 줄에 표시
- 읽기 전용 토큰 → 마찬가지

### 4. 학습 시작 전 검사 (2번보다 뒤)

`--policy.repo_id` 가 있는데 토큰이 없거나 읽기 전용이면 **시작 시점에** 막는다.
지금은 몇 시간 뒤에 안다.

## 안 넣을 것

- **Hub 저장소 만들기·지우기** — huggingface.co 에서 하는 일이다. 우리 UI 가
  그걸 감싸면 권한·과금·공개범위까지 떠안는다
- **여러 계정 전환** — 이 시스템은 기계 하나에 계정 하나다. 조직 전환은 2번의
  네임스페이스 드롭다운으로 충분하다
- **토큰 자동 발급(OAuth)** — HF OAuth 는 콜백 URL 이 필요한데, 로봇 호스트는
  대개 사내망이고 고정 주소가 없다. 붙여넣기가 더 확실하다

## 구현 순서

1 → 3 → 2 → 4. 1번이 없으면 나머지가 의미가 없고, 3번은 1번에 한 줄 얹는 일이다.
