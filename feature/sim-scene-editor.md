# 시뮬 장면 편집 — 테이블 위 사물을 사람이 올린다 (기획)

> [sim-env.md](sim-env.md) 5단계(v2)의 "도메인 무작위화(조명·텍스처·**물체**)"를 앞당겨
> 구체화한다. 거기까지 가려면 먼저 **물체가 하나가 아니어야** 한다.

## 0. 요지 — 정본은 JSON, MJCF 는 굽는 것

사람이 MJCF(MuJoCo XML)를 쓰게 하지 않는다. **장면 JSON** 하나가 정본이고, 그것을
`MjSpec` 으로 구운 모델이 시뮬에 올라간다. 굽는 쪽은 `tools/build_sim_scene.py` 가
URDF 에 대해 이미 하고 있는 일과 같은 발상이다 — 원본은 빌드 때만 읽고 런타임은
산출물만 연다. 다른 점은 **런타임에도 굽는다**는 것뿐이다.

| | 정본 | 누가 쓰나 | 어디 |
|---|---|---|---|
| 팔·테이블·카메라·조명 | `piper_scene.xml` (wheel 패키지 데이터) | `build_sim_scene.py` | 릴리스에 실려 온다 |
| **테이블 위 사물** | **장면 JSON** | **사람 (웹 편집기)** | **데이터 루트** |
| 메시·텍스처 | 업로드 원본 + 볼록 분해 결과 | 사람 | 데이터 루트 |

## 1. 지금의 벽 둘

**① 장면이 wheel 안에 있다.** `piper_scene.xml` 은 `piper_sim` 패키지 데이터로 실려
나간다(`piper_sim = ["assets/*.xml", ...]`). 고치려면 릴리스를 내야 하고, 릴리스를
건너뛴 호스트는 옛 장면을 본다 — .120 이 v0.5.4 게이트웨이에 0.4.7 wheel 로 돌며
옛 바닥·옛 탑뷰를 렌더한 것이 바로 그 사건(2026-09-16)이다. **사람이 올린 사물은
절대 wheel 에 들어가면 안 된다.**

**② 물체 이름이 `cube` 하나로 박혀 있다.** 아래가 전부 그 이름을 안다:

| 자리 | 지금 |
|---|---|
| `piper_sim/scene.py` | `JointMap.cube` = `mj_name2id(..., "cube")` |
| `piper_sim/hub.py` | `cube_pos` · `reset_cube` · `cube_from_view` · `CUBE_START` · `reset(cube_x, cube_y)` |
| `daemons/simd.py` | `_METHODS` 의 `cube_pos` · `reset_cube` · `cube_from_view` |
| 게이트웨이 | `POST /leader/web/cube` (탑뷰 클릭 → 광선 → 테이블 좌표) |
| 조종 창 | `B` 키(블럭 옮기기), `R` 키(환경 리셋) |

다물체로 가면 이 전부가 **id 를 받는 형태**로 일반화된다. `cube` 는 기본 장면에서
id 가 `cube` 인 물체로 남아 하위 호환을 지킨다.

## 2. 오브젝트 데이터 — MuJoCo 가 무엇을 먹나 (실측)

이 기계의 MuJoCo **3.12.0** 으로 직접 확인했다(추측 아님):

| 넣어 본 것 | 결과 |
|---|---|
| `.obj` (Wavefront) | ✅ |
| `.stl` **바이너리** | ✅ |
| `.stl` **ASCII** | ❌ `stl_decoder: number of faces should be between 1 and 200000` |
| `.gltf` · `.glb` · `.dae` · `.ply` | ❌ (파서가 아예 못 연다) |
| 텍스처 `.png` | ✅ |
| 텍스처 `.jpg` | ❌ |

→ **받는 것은 OBJ · 바이너리 STL · PNG 셋뿐이다.** 업로드 창구에서 이 셋만 받고,
ASCII STL 과 GLB/GLTF 는 **거절하되 변환법을 찍어 준다**(둘 다 흔한 내보내기 기본값이라
"왜 안 되는지 모르겠다"가 반드시 나온다).

### ⚠ 메시는 **볼록껍질**로 충돌한다 — 이게 제일 큰 함정

V 자 골짜기 메시를 놓고 공을 떨어뜨렸다:

```
공이 멈춘 높이 z = 0.1096 m   (골짜기 바닥이면 ~0.010, 볼록껍질 위면 ~0.110)
```

공은 골짜기에 **안 들어갔다**. 그릇·컵·트레이·통처럼 오목한 것은 메시 하나로 올리면
겉보기만 오목하고 물리는 **덩어리**다. 지금 장면의 통(`bin`)이 상자 다섯 개인 이유가
이것이다. 답은 둘:

- **볼록 분해**(convex decomposition) — 오목한 메시를 볼록 조각 여러 개로 쪼갠다.
  `CoACD`(최근 표준) 또는 `V-HACD`(고전). `obj2mjcf` 가 이 둘을 감싸 OBJ → MJCF 조각
  (재질별 분리 + 충돌 조각들)까지 한 번에 만든다.
- **프리미티브 조립** — 통·트레이·벽·경사로는 상자 몇 개면 된다. 분해보다 싸고 안정적이다.

## 3. 사람이 사물을 만드는 법 — 쉬운 순서대로

1. **프리미티브** (툴 없음, 웹에서 숫자만) — 상자·원기둥·구·캡슐·타원체. 블럭·캔·공·
   막대·판은 여기서 끝난다. **픽앤플레이스의 대부분이 여기다.** 기본 경로로 삼는다.
2. **조립 프리셋** (툴 없음) — 통·트레이·칸막이·경사로를 프리미티브 조합으로 미리 만들어
   두고 치수만 받는다. 오목한 것을 메시 없이 얻는 유일하게 싼 길.
3. **폰 3D 스캔** → OBJ + PNG — Polycam · Scaniverse · RealityScan · KIRI Engine.
   **진짜 쓸 물건을 그대로 뜬다**는 점에서 sim→real 격차에 제일 유리하다. 다만 스캔은
   ⓐ 단위가 제각각이고 ⓑ 원점이 엉뚱하고 ⓒ 면이 수만~수십만이라 **셋 다 손봐야 한다**(§4 참고).
4. **Blender** (무료) — 직접 모델링하거나 스캔을 정리(데시메이트·원점 이동·단위)한 뒤
   OBJ 또는 **바이너리** STL 로 내보낸다. Blender STL 내보내기는 기본이 바이너리다.
5. **CAD** (FreeCAD · Onshape · Fusion) → STL — 지그·픽스처처럼 치수가 중요한 것.
6. **`obj2mjcf`** — OBJ(+MTL) → 볼록 분해 + MJCF 조각. 3~5 의 산출물을 시뮬에 넣는 마지막 한 칸.

### 만들지 말고 가져오기 — 기성 물체 라이브러리

| 라이브러리 | 규모·성격 | 비고 |
|---|---|---|
| **YCB Object & Model Set** | 약 77종, 조작 연구의 사실상 표준(머스터드·크래커 상자·바나나·머그…) | 텍스처 메시 제공, MJCF 포팅본이 여럿 있다 |
| **Google Scanned Objects** | 약 1000종 생활용품 스캔, OBJ+PNG | 라이선스가 관대한 편 — **쓰기 전 확인** |
| **MuJoCo Menagerie** | MJCF 정식 모델 모음 | 로봇 위주, 소품 일부 |
| **Objaverse** | 수십만 종 | GLB 라 변환 필요, 품질 편차 큼 |

→ 1단계에선 **아무것도 번들하지 않는다**. 라이선스가 제각각이라 배포본에 실으면
그 부담이 우리에게 온다. 대신 §4 의 자산 라이브러리에 **사람이 가져다 넣는** 길만 연다.

## 4. 저장 포맷 — 장면 JSON(정본) + 자산 라이브러리

```jsonc
{
  "version": 1,
  "id": "two-blocks-and-bin",
  "name": "블럭 두 개 + 통",
  "objects": [
    { "id": "cube", "label": "빨간 블럭",
      "shape": "box", "size": [0.02, 0.02, 0.02],
      "pos": [0.35, 0.0, 0.02], "euler_deg": [0, 0, 0],
      "rgba": [0.85, 0.2, 0.15, 1], "mass": 0.05, "movable": true,
      "physics": { "friction": [2.0, 0.1, 0.001], "condim": 6, "solref": [0.005, 1] } },

    { "id": "bin", "label": "파란 통", "shape": "preset:bin", "movable": false,
      "pos": [0.35, -0.25, 0], "rgba": [0.2, 0.35, 0.7, 1],
      "params": { "inner": [0.08, 0.08], "wall_h": 0.03, "floor_t": 0.003 } },

    { "id": "mug", "label": "머그컵", "shape": "mesh", "asset": "a7f3c1…",
      "scale": 1.0, "pos": [0.30, 0.15, 0.0], "mass": 0.12, "movable": true }
  ]
}
```

왜 MJCF 를 직접 안 받는가:

- **검증된다.** 숫자 범위·필수 키를 스키마로 막는다. XML 을 그대로 먹이면 사람이 올린
  문자열이 `<option>`·`<contact>`·액추에이터까지 건드려 팔의 물리를 바꿀 수 있다.
- **폼으로 그릴 수 있다.** 브라우저에서 슬라이더·색 선택기로 편집한다.
- **id 가 안정적이다.** §1 의 `cube` 자리들이 전부 id 를 받는 형태로 일반화되고,
  데이터셋 메타·평가 판정이 "그 장면의 그 물체"를 가리킬 수 있다.
- **작고 diff 된다.** 장면을 공유·복제·버전 관리하기 좋다.

### 자산(메시) 레코드

```jsonc
{ "id": "a7f3c1…", "name": "머그컵", "file": "mug.obj", "format": "obj",
  "texture": "mug.png",
  "raw_bbox_m": [0.082, 0.081, 0.095],     // 원본 그대로 잰 크기 — 단위 사고를 여기서 잡는다
  "scale": 1.0,
  "collision": { "method": "coacd", "parts": 12, "built_at": "…" },
  "license": "사용자 입력", "added_at": "…" }
```

업로드 때 **반드시 하는 셋** (스캔·CAD 가 전부 걸린다):

1. **크기 재서 보여 준다** — "이 메시는 82 × 81 × 95 mm 입니다. 맞습니까?" mm 로 뜬 모델은
   `scale: 0.001`. 단위가 없는 포맷이라 시스템이 알아낼 방법이 없다 — **사람에게 묻는 것이 정답**이다.
2. **바닥에 앉힌다** — AABB 아래면을 원점으로 맞춰, 놓으면 테이블에 앉게 한다.
3. **볼록 분해** — 오목이면 조각으로. 면 수가 크면 데시메이트도(렌더는 원본, 충돌은 조각).

## 5. 굽기 — `MjSpec` (MuJoCo 3.12)

문자열 템플릿이 아니라 `mujoco.MjSpec` 으로 조립한다. **실제 장면에 얹어 확인했다**:

```
base bodies: 13
with 3 objects: nbody=16 nq=36   1초 물리 0.015s
  obj0 안착 z=0.0200   obj1 안착 z=0.0500   obj2 안착 z=0.0248
팔 관절 살아있나: True
카메라: ['top', 'front', 'wrist']
```

`MjSpec.from_file(piper_scene.xml)` → `worldbody.add_body()` → `add_freejoint()` →
`add_geom()` → `compile()`. 팔 관절도 카메라 이름도 그대로 살고, 물체 셋을 얹어도
물리 1초가 15ms 다(실시간 예산 1000ms 의 1.5%). 여유는 충분하다.

## 6. 어디에 두나 — **wheel 이 아니라 데이터 루트**

```
<config_dir>/sim_scenes/            # 컨테이너: /data/config/sim_scenes
  <id>.json                         # 장면 하나 = 파일 하나
  .current                          # 지금 올라간 장면 id
<config_dir>/sim_assets/<asset-id>/ # asset-id = 내용 해시 16자 (같은 파일은 한 번만)
  mesh.obj | mesh.stl
  meta.json                         # 잰 값 · 사람이 확인한 unit_scale
```

### ⚠ 메시는 **id 만 싣고 양쪽이 자기 루트에서 푼다**

장면 명세는 dict 로 통째로 넘기지만(아래) 메시는 파일이라 그럴 수 없다 — 몇 MB 를 버스로
보낼 수는 없다. 그래서 자산은 **id** 로만 가리키고, 게이트웨이(`PIPER_CONFIG_DIR=/data/config`)
와 simd(유닛이 박는 호스트 경로)가 각자 자기 루트에서 같은 상대경로를 연다. 둘은 같은 물리
디렉토리다 — compose 가 그 디렉토리를 `/data` 로 마운트한다.

게이트웨이는 **추정하지 않는다**(`assets.use_config_dir`): 한 기계에 배포본과 개발 체크아웃이
같이 있으면 `/srv/piper-data` 가 존재해 데몬 쪽 규칙은 그걸 고르는데 개발 게이트웨이는
`~/.config/piper-web` 을 쓴다 — "올렸는데 시뮬에 없다"가 된다.

§1 의 이유 그대로다. `config_dir` 아래인 것은 장면이 카메라 프로파일·프리셋과 같은
성격(사람이 쓴 작은 JSON)이고, 그 경로가 **이미 데이터 루트로 마운트돼 있어** 새 마운트가
필요 없어서다.

### ⚠ 데몬에는 **id 가 아니라 명세를 보낸다** (2026-09-17 설계 변경)

이 절은 원래 "simd 가 같은 경로를 호스트 쪽에서 읽는다"였다. **틀렸다.** 컨테이너는 이
디렉토리를 `/data/config/sim_scenes` 로, 호스트의 simd 는
`/srv/piper-data/config/sim_scenes` 로 본다 — 같은 id 가 서로 다른 경로다. 데몬에게 id 를
말하면 그 차이가 언젠가 조용히 문다(컨테이너 안에서 `ip` 를 부르던 것과 같은 종류의 실수다).

그래서 **게이트웨이가 파일을 읽어 명세 dict 를 통째로 넘긴다.** 데몬은 파일 시스템을 안 본다.
대가는 하나: simd 가 재시작하면 명세가 메모리에서 사라져 기본 장면으로 돌아온다. 그 불일치는
게이트웨이가 본다(`sim_scenes.ensure_applied()`, 기동할 때 + 시뮬 팔을 붙일 때) — 카메라
프로파일을 연결 때 다시 적용하는 것과 같은 규율이다. 안 보면 사람은 자기 세계가 올라가
있다고 믿은 채 **엉뚱한 장면에서 수집한다.**

## 7. 런타임 — 장면 갈아끼우기

`simd` 에 `load_scene(scene_id)` 를 새로 낸다. 갈아끼우기는 **모델 재컴파일 + MjData 신규**라
공짜가 아니다. 지켜야 할 것:

- **팔 자세를 보존한다** — 새 `MjData` 에 옛 `qpos`(팔·손가락)를 옮겨 심고 `hold()`.
  안 그러면 갈아끼울 때마다 팔이 원점으로 튄다.
- **렌더러는 렌더 스레드에서 다시 만든다** — EGL 컨텍스트는 스레드 귀속이다. sim-env
  2단계에서 이걸 어겨 5분에 EGLError 139회가 났다. 재생성 요청도 그 큐로 보낸다.
- **이름 계약을 깨지 않는다** — `joint1..6`·`gripper_l/r`·`link6`·카메라 `top/front/wrist`.
  사람이 올린 물체가 이 이름을 쓰면 **거절**한다(id 예약어).
- **작업 중엔 못 바꾼다** — 수집·추론·조종 중 교체는 배타(`exclusivity`)로 막는다.
  에피소드 한가운데 세계가 바뀌면 그 데이터는 쓰레기가 된다.
- **물체 수 상한** — 실시간 500Hz 를 지켜야 하므로 상한을 둔다(§5 측정 기준 여유는 크지만
  메시 물체는 이야기가 다르다 — 상한은 측정해서 정한다).

## 8. UI — **편집기는 독립 페이지다** (사용자 결정 2026-09-17)

설정 탭이나 로봇 카드 안에 끼워 넣지 않는다. `/scene` 으로 **자기 페이지**를 갖는다
(`PAGE_GROUPS` 의 `장치`, `pages.ts` 에 한 줄). 이유:

- 편집은 **작업**이지 설정이 아니다 — 물체 목록·배치 화면·자산 라이브러리가 한 화면에
  들어가야 하고, 설정 카드 하나에 그걸 밀어 넣으면 [화면 레이아웃 개편](layout-redesign.md)이
  지적한 "자리가 없어 밀려난 화면"이 하나 더 생긴다.
- 장면은 로봇에 딸린 속성이 아니다 — 여러 장면을 만들고 고르고 복제한다. 로봇 카드에
  붙이면 "지금 붙은 시뮬 팔"이 없으면 편집도 못 하게 된다.
- 조종 창과도 분리한다. 조종 창은 **조종**만 한다 — 지금 있는 `B`(클릭한 자리로 블럭
  옮기기)는 조종 중의 빠른 리셋이라 그대로 두고, 물체를 **만들고 지우는** 일은 편집기에서만.

페이지 구성:

- **장면 목록** — 만들기·복제·이름 바꾸기·지우기·**적용**(simd 에 `load_scene`).
  지금 올라간 장면을 표시한다.
- **환경 불러오기 / 내보내기** — 파일 하나로 주고받는다 (사용자 요청 2026-09-17:
  "그 파일을 환경 불러오기로 불러오는거지"). 장면 JSON 을 그대로 올리고 그대로 내려받으니
  기계 사이 이사·공유·백업이 전부 같은 한 가지 동작이다. 불러오기는 `scene_spec.validate`
  를 그대로 타므로 **깨진 파일이 시뮬에 못 닿는다** — 몇 번째 줄이 틀렸는지까지 말해 준다.
  ⚠ 메시를 쓰는 장면은 자산이 함께 가야 한다(§4) — 3단계에서 zip 으로 묶는다.
- **배치 화면** — 탑뷰 카메라 프리뷰 위에서 선택·드래그·회전. 광선→테이블 좌표 코드는
  `POST /leader/web/cube`(조종 창의 `B`)에 **이미 있다** — 그걸 물체 id 를 받는 형태로
  일반화해 재사용한다(§1).
- **물체 패널** — 추가(프리미티브·프리셋·자산) + 선택 물체 폼(크기·색·질량·마찰·고정 여부).
- **자산 라이브러리** — 업로드(§4 의 셋: 크기 확인·바닥 앉히기·볼록 분해), 썸네일,
  어느 장면이 쓰는지.
- 미리보기는 기존 sim 카메라 프리뷰 그대로 쓴다(새로 만들 렌더 경로 없음).

로봇 페이지의 시뮬 카드에는 **링크 하나**만 둔다 — "장면 편집" → `/scene`.

## 9. 순서

1. **장면 JSON + 굽기 + `load_scene`** — 기본 장면이 지금의 큐브+통과 **픽셀 단위로 같게**
   나오는 것이 완료 조건이다(회귀 없음). `cube` 자리들(§1 표)을 id 받는 형태로 일반화.
   - ☑ **1a (2026-09-17) — 포맷과 굽는 층.** `piper_sim/scene_spec.py`(스키마·검증·`MjSpec`
     합성·`load()`), `assets/default_scene.json`(큐브+통), 바탕 XML 에서 그 둘 제거,
     `load_model(spec=None)` 위임, `JointMap.objects`(월드 직계 자식 − 팔 뿌리 → id 표).
     실측: 재구성한 모델이 `nq=15 nbody=13 ncam=3` 으로 **옛 씬과 같고**, 큐브의
     pos·질량·size·condim·friction·solref 가 자리마다 일치하며, 기울어진 파지 시험
     (`test_sim_grasp.py`) 네 경우가 그대로 붙잡는다. 통 안에 떨어뜨린 공이 z=0.018 에
     앉는 것으로 프리셋의 오목함이 물리에 사는 것도 확인(볼록껍질이면 0.06).
     잡은 것 하나: `test_sim_grasp.py` 가 큐브 geom 을 **XML 문자열에서 정규식으로** 떼어
     쓰고 있어, 이사하자 실험이 통째로 죽었다 — 이제 `scene_spec` 에서 읽는다.
   - ☑ **1b (2026-09-17) — 갈아끼우기와 API.** `World.load_scene`(**컴파일 먼저** → 실패해도
     옛 세계 그대로, 팔 qpos 이식 + `hold` 로 튐 방지, `on_model_change` 로 렌더러 무효화),
     `World.objects/place/ray_to_table/object_from_ray`, `reset` 이 **움직이는 물체 전부**를
     장면이 적은 자리로(시작 자리가 상수 → 장면 JSON), `scene_spec.rest_z`(모양별 안착
     높이 — 상수 0.02 는 큐브에만 맞았다), hub 의 `scene/load_scene/objects/place_object/
     object_from_view` + simd `_METHODS`, 게이트웨이 `sim_scenes` 스토어와 `/api/sim/scenes`
     (목록·저장·지우기·적용·**불러오기/내보내기**·`defaults`·`live/objects`·`live/place`),
     기동 시 `ensure_applied()`, 이미지에 `piper_sim`(`--no-deps` — mujoco 는 안 딸려 온다).
     잡은 것 셋: ① 렌더러는 **만들 때의 모델**을 쥔다 — 안 버리면 장면을 갈아도 옛 세계를
     계속 그린다(버리는 일은 렌더 스레드가 한다, EGL 스레드 귀속). 조명 기준값
     `_light_base` 도 같이 버린다. ② `sim_robot_client.call()` 은 무엇이 잘못돼도 `default`
     를 돌려줘 "왜 거절당했는지"를 삼킨다 → 사람이 고칠 수 있는 실패용 `call_strict` 를 나눴다.
     ③ 탑뷰 클릭 테스트가 `World.__new__` 로 뼈대만 만들어 써서 물체 정보가 생기자 죽었다 —
     진짜 `World` 로 바꾸고 "큐브가 실제로 거기 간다"까지 잰다.
   - ☑ **1c (2026-09-17) — 작업 중 교체 금지 + 연결 때 재적용.**
     `Activity.SCENE_SWAP`(상태 없는 자원 접근 — 남을 막지 않고 막히기만 한다)을 배타 표에
     넣어 수집·추론·에피소드 루프·텔레옵 중에는 `apply()` 가 거절한다. 교체는 모델 재컴파일
     + MjData 신규라 에피소드 한가운데 하면 앞뒤가 다른 세계에서 모인 데이터가 되고,
     **관측이 바뀐 것을 라벨은 모른다.** `ensure_applied()` 도 같은 판정을 거치므로 기동·연결
     확인이 에피소드를 깨지 않는다. 시뮬 팔 `/attach`(= simd 가 World 를 만드는 순간)에서도
     한 번 더 확인한다.
     ⚠ 잡은 구멍 하나: **조종 창(웹 리더)은 `Activity.TELEOP` 에 안 잡힌다** — 그 활동의
     상태 제공자는 CLI 텔레옵 세션이고 웹 리더는 자기 서비스다. 시뮬을 모는 사람은 십중팔구
     조종 창을 쓰므로 `busy_reason()` 이 따로 본다. 안 봤으면 팔을 몰고 있는 사람 밑에서
     세계가 사라진다.
2. ☑ **편집기 페이지(`/scene`, 프리미티브·프리셋)** (2026-09-17) — 툴 없이 사물을 올린다.
   `frontend/src/pages/ScenePage.tsx` + `pages.ts` 의 `장치` 묶음 한 줄. 장면 목록(새로·복제·
   지우기·적용), 물체 목록과 추가(프리미티브 다섯 + `preset:bin`), 선택 물체 폼(라벨·색·
   위치·크기·회전·질량·마찰·고정 여부), 탑뷰 클릭 배치, **환경 불러오기/내보내기**.
   화면은 모양·프리셋·접촉 기본값·물체 상한을 `/defaults` 에서 읽는다 — 목록을 두 곳에
   적지 않는다. 광선 계산도 데몬에 맡긴다(`live/place-from-view`).
   ⚠ 배치는 **적용된 장면일 때만** 받는다. 안 그러면 사람은 이 장면을 고치고 있다고 믿으면서
   다른 세계를 건드린다 — 화면이 덮개로 막고 왜 못 누르는지 말한다.
   ⚠ 한 가지는 두 곳에 있다: 새 물체를 테이블에 앉힐 높이(`rest_z`). 물체를 추가할 때마다
   서버에 물을 수 없어서다 — 테스트가 양쪽을 묶어 둔다.
   잡은 것 하나: 내보내기는 `api.get` 을 못 쓴다(무조건 `res.json()` 이라 파일이 아니라
   파싱된 객체가 온다) → `fetch` + `res.text()`. 그리고 그 사실을 적은 **주석이** "api.get
   금지" 검사에 걸렸다 — `conftest.code_only` 로 걷는다(이 저장소에서 세 번째다).
3. ◐ **자산 라이브러리** (2026-09-17) — 스캔한 실물이 들어온다.
   `piper_sim/mesh.py`(읽기·재기, 의존성 0), `piper_sim/assets.py`(저장소 — 게이트웨이가
   쓰고 simd 가 읽는 **한 구현**), 게이트웨이 `sim_assets` + `/api/sim/assets`, 편집기의
   자산 패널, 장면 명세의 `shape: "mesh"`.
   - **포맷**: OBJ · 바이너리 STL 만. ASCII STL·GLB·DAE·STEP·JPG 는 거절하되 **무엇으로
     바꿔 오면 되는지** 말한다(전부 흔한 내보내기 기본값이다).
   - **단위**: m·cm·mm 중 "테이블 위 물건 ≈ 10cm" 에 로그 거리로 제일 가까운 것을 추측하고
     화면이 확인받는다. ⚠ "범위에 드는 첫 배율"은 틀린다 — 20×30×40 은 cm(40cm)도 범위에
     들지만 CAD 의 mm(4cm)일 때가 훨씬 흔하다(실제로 그렇게 골랐다).
   - **바닥**: AABB 아래면 가운데를 물체 원점으로. 실측 — MuJoCo 는 메시를 자기 무게중심으로
     옮기고 geom 위치로 되돌리므로 파일 원점이 곧 geom 프레임이다. 그 위에 이 보정을 얹으면
     body z 가 **-0.0002** 로 안착한다.
   - **오목함**: 면마다 평면을 긋고 꼭짓점이 한쪽에만 있는지 본다. ⚠ 처음엔 "평면 바깥으로
     나간 거리"로 쟀는데 그건 법선 방향을 믿는 것이라 V 자 골짜기의 0.1m 를 **0** 으로
     답했다. 한쪽/양쪽만 보면 방향이 필요 없다(실측: L 자 프리즘 1.0, 뒤집어도 1.0).
   - **용접**: ⚠ STL 은 꼭짓점을 삼각형마다 복제한다 — 용접 전에 재면 **닫힌 솔리드가 전부
     "열림"** 으로 나온다(실측: 정사면체 STL 12정점 → 4정점).
   - ☐ **볼록 분해는 아직이다.** CoACD·V-HACD 는 새 의존성이고(게이트웨이 이미지가 커진다)
     이 기계에는 trimesh·coacd·VHACD 어느 것도 없다. 지금은 **충돌이 볼록껍질**이라는 사실과
     파인 깊이(mm)를 화면이 경고하고, 오목한 그릇·통은 `preset:bin` 으로 짓게 한다. 들일지는
     사람이 정할 일이라 열어 둔다.
4. ☑ **장면을 데이터셋·평가에 붙인다** (2026-09-17) — 이게 없으면 장면을 늘릴수록 데이터가
   섞이고, **나중에 붙여도 소급이 안 된다**(그 전 에피소드는 어느 세계였는지 아무도 모른다).
   - 데이터셋 사이드카 `meta/piper_scene.json` — 카메라 사이드카와 같은 자리·같은 이유
     (`meta/` 면 허브 업로드에 동반되고 LeRobot 은 모르는 파일을 안 건드린다).
     ⚠ **이름이 아니라 명세를 통째로** 담는다. 사람이 장면을 계속 고치므로 나중에 그 이름의
     장면은 다른 세계다 — 통째로 담아야 데이터셋이 자기 설명이 되고 다른 기계에서 다시
     지을 수 있다(메시는 자산 id 로 가리킬 뿐이라 함께 옮겨야 한다).
   - 장면은 **시작 때** 붙잡는다(카메라 매핑과 같은 자리) — 사이드카는 데이터셋이 만들어진
     뒤에야 쓸 수 있어 정지 시점에 쓰지만, 그때 읽으면 늦다. 교체는 1c 가 막아 두므로
     시작 때의 장면이 곧 끝의 장면이다. 양팔(`robot_ports`)도 본다.
   - `/eval/log` 가 지금 올라간 장면을 **자동으로** 박고(화면이 알 필요 없다) `/eval/stats` 에
     `by_scene` 이 생긴다. ⚠ 장면이 여럿이면 장면을 안 가른 성공률은 **쉬운 세계와 어려운
     세계의 평균**이라 그걸 보고 체크포인트를 고르면 잘못 고른다.
   - 화면: 데이터셋 목록에 🧱 장면 이름, 평가 패널에 장면별 성공률.
5. **도메인 무작위화** — 장면 JSON 에 `randomize` 절(위치 지터·색·조명·마찰 범위).
   sim-env 5단계가 여기로 흡수된다.

## 10. 위험

| 위험 | 대응 |
|---|---|
| 사람이 올린 물체가 팔·카메라 이름을 덮어쓴다 | id 예약어 거절 + 컴파일 뒤 이름 계약 검증(테스트) |
| 오목 메시를 그대로 올려 "잡히는데 안 잡힌다" | 업로드에서 볼록성 판정 → 오목이면 분해를 **강제**하고 결과를 보여 준다 |
| 단위 사고(mm 모델이 1000배로 뜬다) | 업로드 때 잰 크기를 mm 로 보여 주고 사람이 확인 |
| 물체가 늘어 실시간 500Hz 가 밀린다 | `World.lag_s` 가 이미 밀린 시간을 잰다 → 상한 + 화면 경고 |
| 장면이 바뀌어 옛 체크포인트의 관측과 달라진다 | 9-4(장면 메타) — 데이터셋·평가에 장면 id 를 남긴다. sim-env 의 탑뷰 변경 때 이미 겪었다 |
| 편집 중 교체로 에피소드가 깨진다 | 작업 중 교체 금지(배타) |

## 열린 질문

- 장면 JSON 을 **누가 검증하나** — 게이트웨이(pydantic)인가 `piper_sim` 인가. 데몬도
  자기 입력을 믿으면 안 되니 양쪽이지만, 스키마 정본은 한 곳이어야 한다.
- 프리셋(`preset:bin`)을 **어디까지** 둘 것인가 — 통·트레이·칸막이·경사로 넷이면 충분한가.
- 볼록 분해를 **어디서** 도나 — 컨테이너(게이트웨이)에 CoACD 를 넣을지, 호스트 venv 에
  넣을지. 업로드는 게이트웨이가 받으므로 컨테이너가 자연스럽지만 이미지가 커진다.
- 자산·장면을 **기계 사이로 옮기는** 방법 — 내보내기/가져오기 zip 하나면 되는가.
