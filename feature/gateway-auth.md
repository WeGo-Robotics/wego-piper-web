# 게이트웨이 로그인

LAN 의 누구나가 아니라 **아는 사람만** 들어오게 한다. 2026-09-22.

## 1. 왜

`/api/ext/v1` 말고는 인증이 아예 없었다. 같은 네트워크에서 `:8000` 에 닿으면 누구나

- 데이터셋·모델을 지우고,
- 추론·텔레옵을 시작해 **팔을 움직이고**,
- Vast API 키가 저장된 호스트에서는 **GPU 를 빌려 돈을 쓸 수 있었다.**

마지막 것이 계기였다(클라우드 학습을 붙이면서 키를 호스트에 저장하게 됐다). 앞의 둘은
그전부터 그랬고, LAN 신뢰를 전제로 넘어가던 것이다.

## 2. 켜야 걸린다 — 기본은 꺼짐

⚠ **"기본 잠김" 으로 만들지 않았다.** 그러면 릴리스를 받는 순간 배포된 로봇이 전부
잠긴다. 현장에서 화면이 안 열리는 것은 안전 기능이 아니라 사고다.

대신 **꺼진 상태를 화면이 경고한다**(설정 → 보안). 안 켜는 것은 선택일 수 있어도, 모르고
열려 있는 것은 아니다.

⚠ 그래서 **처음 정하는 사람은 아무나일 수 있다.** 먼저 정한 사람이 주인이 된다. 사전
신뢰가 없는 LAN 장비의 부트스트랩은 원래 그렇고, 답은 "설치 직후에 정한다" 다.

## 3. ⚠⚠ E-stop 은 어떤 경우에도 인증을 안 탄다

`/api/estop/*` 는 관문이 통째로 비켜 간다. 이유는 둘이고 둘 다 무겁다:

1. **멈추는 것을 막을 이유가 없다.** 비밀번호를 모르는 사람이 팔을 세우려는 것을 막는
   인증은 안전 장치가 아니라 위험 장치다.
2. **heartbeat 가 401 이면 돌던 추론이 죽는다.** estopd 는 heartbeat 가 끊기면 "브라우저가
   죽었다" 로 읽고 2.5초 뒤 SIGKILL 한다(실측 전례). 세션이 만료된 채 추론이 돌고 있으면,
   인증을 붙인 대가로 학습 결과를 시연하던 중에 팔이 서는 것이다.

테스트가 이걸 못 박는다 — `test_estop_is_never_behind_the_door`.

## 4. 무엇이 열려 있나

| 경로 | 왜 |
|---|---|
| `/api/estop/*` | §3 |
| `/api/auth/*` | 로그인 자체. 상태 질문이 로그인을 요구하면 아무도 시작 못 한다 |
| `/health` | 컴포즈·감시가 본다 |
| `/api/ext/v1/*` | 자기 Bearer 가 이미 있다(`PIPER_API_TOKEN`). 세션까지 요구하면 **로그인 화면이 없는 외부 클라이언트가 통째로 끊긴다** |
| `OPTIONS` | CORS 프리플라이트는 본 요청이 아니다 |

나머지 `/api/*` 와 `/ws` 는 세션 쿠키가 필요하다.

## 5. 만든 것

| | |
|---|---|
| `services/auth.py` | 비밀번호(PBKDF2)·세션 토큰(HMAC)·무차별 대입 지연 |
| `core/authgate.py` | **순수 ASGI** 미들웨어 |
| `routers/auth.py` | `status`·`login`·`logout`·`password`(PUT/DELETE) |
| `components/AuthGate.tsx` | 앱 전체를 감싸는 관문 + 로그인 화면 |
| `components/AccessPanel.tsx` | 설정 → 보안 |

### ⚠ `BaseHTTPMiddleware` 를 안 쓴 이유

둘이 안 된다: **WebSocket scope 를 아예 못 보고**(`/ws` 가 인증 밖에 남는다), 끝나지
않는 응답(MJPEG 프리뷰)과 안 맞는다. 순수 ASGI 로 짜서 `scope` 만 보고 결정하고,
통과시킬 때는 아무것도 감싸지 않는다.

### ⚠ 표준 라이브러리만 쓴다

`itsdangerous` 도 `passlib` 도 안 쓴다. 배포 이미지는 `pip install --no-deps` 라 새
의존성이 **안 깔린다**(`backend/Dockerfile`) — 잘 되는 줄 알고 릴리스했다가
`ModuleNotFoundError` 로 게이트웨이가 아예 안 뜨는 쪽이 훨씬 나쁘다.

### ⚠ 쿠키다, 헤더가 아니다

MJPEG 프리뷰(`<img src>`)와 WebSocket 은 브라우저가 알아서 쿠키를 싣는다. `Authorization`
헤더로 했으면 그 둘이 따로 새는 구멍이 된다. `secure=True` 는 **안 준다** — 현장은
`http://192.168.0.120` 으로 열고, 주면 쿠키가 저장조차 안 돼서 "로그인은 성공했는데 계속
로그인 화면" 이 된다.

### ⚠ 세션은 서버에 안 쌓는다

HMAC 서명 토큰이라 재시작해도 살아남는다. 게이트웨이는 릴리스·설정 변경으로 자주
재시작하는데, 그때마다 전원이 로그아웃되면 사람이 인증을 꺼 버린다.

역으로 **비밀번호를 바꾸면 서명 비밀도 새로 나서 돌아다니던 세션이 전부 죽는다.** 바꾸는
이유가 보통 "남이 알아버렸다" 이므로 그게 맞는 동작이다.

## 6. 짧은 비밀번호를 허용한 대가는 지연으로 낸다

현장에서 PIN 을 쓰므로 최소 4자다. **대신** 5회부터 지수 지연이 붙는다(최대 60초).
둘 중 하나만 있으면 안 된다.

⚠ 지연은 프로세스 메모리에만 있다 — 재시작하면 풀린다. 재시작할 수 있는 사람은 이미
호스트를 쥔 사람이라 더 막아도 의미가 없다.

## 7. 실측 (2026-09-22)

```
1. 처음 상태            {"enabled":false,"authenticated":true}
2. 인증 없이 모델 목록   HTTP 200
3. 비밀번호 설정 뒤      {"enabled":true,"authenticated":false}
4. 쿠키 없이 모델 목록   HTTP 401
5. 쿠키 없이 heartbeat   HTTP 200   ← 막히면 안 된다
6. 쿠키 없이 health      HTTP 200
7. 로그인 뒤 모델 목록   HTTP 200
8. 틀린 비번             HTTP 401
9. 인증 끈 뒤            {"enabled":false,"authenticated":true}
```

테스트 `test_gateway_auth.py` 18개. 전체 **2316 통과**.

## 8. 아직 안 한 것

- **사용자 구분이 없다.** 비밀번호 하나를 공유한다. 누가 무엇을 했는지 로그로 못 가른다.
- **HTTPS 가 아니다.** 같은 LAN 에서 패킷을 보는 사람에게는 비밀번호가 그대로 보인다.
  현장 배선이 http 라 지금은 여기까지다.
- **잊었을 때 푸는 길은 파일 삭제뿐**이다 — 호스트에서 `~/.config/piper-web/auth.json`
  (컨테이너는 `/data/config/auth.json`). 화면이 그 경로를 말해 준다(설정 파일이 깨졌을 때).
