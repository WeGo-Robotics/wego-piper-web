# 카메라 해상도 — 학습 때와 같은 화면으로 추론한다

상태: **☑ 구현** (2026-10-26) — 요청 해상도 유지 · 학습 카메라 판정 · 시작 검사 · 화면 표시 · [맞추기].
남은 것: 아래 "하지 않은 것".

## 왜

2026-10-26, 지난주에 잘 되던 SmolVLA 가중치가 사과를 **조금씩 엇나간 자리**로 집으러 갔다. 코드는 범인이 아니었다.

| | top (D435I) | hand (D405) |
|---|---|---|
| 학습 데이터셋 | 640×480 @15 | 640×480 @15 |
| 지난주 추론 | 640×480 (직전 녹화가 남긴 요청) | 640×480 |
| 오늘 추론 | **1280×720 @30** | **848×480 @30** |

- 추론은 해상도를 요청하지 않고 **돌고 있는 그대로** 쓴다(`prepare_cameras`). 지난주에는 매번 녹화 직후라 녹화가
  남긴 640×480 이 살아 있었다.
- 10-23 17:02 USB 사고로 rsd 가 코어덤프로 재시작했다. **요청 해상도는 데몬 메모리에만** 있었으므로 다음 연결이
  장치 기본값으로 열렸다.
- SmolVLA 는 영상을 비율을 지켜 512×512 로 줄이고 빈 곳을 채운다. 4:3 이 16:9 가 되면 같은 장면이 다른 크기·
  자리로 들어간다 — 정책은 에러 없이 엇나간다.

왜 아무도 못 봤나:

- 추론 화면 카메라 줄의 `256x256` 은 **모델 config 의 입력 크기**였다. SmolVLA 처럼 베이스에서 시작하면
  베이스 값이 남는다 — 학습 해상도가 아니다.
- 지금 해상도는 드롭다운 글자 안에만 있었다. 비교할 학습 값이 옆에 없었다.
- 검증에 해상도 경고가 **있었는데** 그 config 값과 카메라 **요청값**(안 정했으면 None → 건너뜀)을 비교해 한 번도
  울리지 않았다.
- 카메라 페이지도 요청값만 보여서, 정하지 않았으면 해상도 칸이 비었다.

## 무엇을 했나

### 1. 요청 해상도를 게이트웨이가 들고 있는다 — 데몬이 재시작해도 유지

`CameraInfo.width/height/fps`(세션 파일의 `config`)를 **요청 해상도**로 쓴다. 전에는 저장만 되고 아무도 안 읽었다.

- 명시해 열면(`connect(w, h, fps)` — 녹화, [맞추기], 카메라 페이지) 그 값을 저장한다.
- 해상도 없이 열면(카메라 페이지·추론 화면의 [연결], 등록) **저장된 값으로** 연다. 없으면 장치 기본값.
- 그래서 rsd·camerad 가 재시작하거나 USB 가 다시 붙은 뒤의 [연결]도 같은 크기로 열린다.
- 녹화가 연 해상도도 저장된다 — "재시작해도 해상도가 바뀌지 않는다" 를 지키려면 지금 돌고 있는 요청을 남겨야 한다.
  카메라 설정의 Width·Height·FPS 칸이 이 값이다(바꾸면 다음 연결부터).

### 2. 모델에 학습 해상도 — `services/train_cameras.py`

판정 순서는 `action_space` 와 같은 모양이다:

1. 체크포인트의 표식 `piper_train_cameras.json` — **추론을 시작할 때** 남긴다. 데이터셋을 지워도 남는다. HF 캐시
   스냅샷엔 쓰지 않는다.
2. `train_config.json` 의 데이터셋 → `meta/info.json`(크기 — 모든 LeRobot 데이터셋) + `meta/piper_cameras.json`
   (fps·기종·캡처 크기 — 우리가 녹화한 것만).
3. 둘 다 없으면 모른다 — 대조하지 않는다.

이름은 **데이터셋 쪽**(top/hand) — 추론 매핑의 키와 같다. 녹화 사이드카에 **기종**(`model`, 카메라 페이지의 장치명)과
**캡처 크기**(`capture_width/height`)를 새로 남긴다. 기종이 없는 옛 데이터셋은 RealSense 만 지금 등록된 같은
시리얼의 이름을 빌린다(`/dev/videoN` 은 재열거로 다른 장치일 수 있어 짐작하지 않는다).

### 3. 대조 규칙

학습 크기와 **지금 발행 중인 크기**(세그먼트 헤더 — 요청값이 아니다)를 비교한다.

| 상황 | 판정 |
|---|---|
| 크기가 같다 | 통과 (fps 는 안 본다 — 녹화·제어 루프가 정한다) |
| 비율이 같고 크기만 다르다 | **경고**, 실행된다 |
| 비율이 다르다 (허용 1% — D405 848×480 은 16:9) | **시작을 막는다** |
| 기종이 다르다 | 경고 |
| 학습 쪽을 모른다 | 아무 말 안 함 |

- 화면 검증(`/api/inference/validate`)과 시작(`/models/inference/start`, 손으로 고친 명령의 `--cameras` 포함)이
  **같은 함수**를 탄다. 화면만 믿지 않는다.
- 실행 중에는 검사하지 않는다 — 추론 중에는 카메라 연결·해상도 변경이 409 로 막혀 있다.

### 4. 화면

| 자리 | 보이는 것 |
|---|---|
| 추론 — 카메라 줄 아래 | `학습 640×480@15 · D435I Color   지금 1280×720@30  ✗ 화면 비율이 다름` |
| 추론 — [학습 해상도로 맞추기] | 크기·비율이 다를 때. 학습 때처럼 다시 열고 저장(`POST /api/cameras/match-training`) — 넓게 받아 줄였던 데이터면 캡처·출력까지 재현 |
| 추론 — 카메라 미리보기 | 이름 옆 실제 해상도, 다르면 노랑 `1280×720 ≠ 640×480` |
| 모델 상세 | `학습 해상도` · `기종` · `모델 입력`(config 값, 구분해서) |
| 카메라 카드 | 지금 발행 크기 · `요청 640×480@15`, 요청이 없으면 주황 `요청 해상도 없음` |

## 하지 않은 것

- **데몬 재시작 뒤 자동 재연결.** 지금처럼 [연결]을 눌러야 한다 — 누르면 저장된 해상도로 열린다.
- **같은 크기·다른 화각.** 640×480 을 센서를 잘라 연 것과 1280×960 을 줄인 것은 화각이 다르다. 캡처 크기는 이번부터
  녹화 사이드카에 남으므로, 앞으로의 데이터셋은 [맞추기]가 재현한다. 대조(경고)에는 아직 넣지 않았다.
- 정책 서버 모드의 서버 쪽 카메라 — 카메라는 이 기계 것이라 같은 검사를 받는다.
