# ACT-delta — 절대 위치 대신 이동 변화량을 학습한다 (기획)

상태: **기획.** 구현 전.

## 왜

ACT는 지금 관절의 **절대 위치**를 액션으로 학습한다. 이 저장소에서 그 대가를
이미 두 번 치렀다:

1. **캘리브레이션이 바뀌면 체크포인트가 통째로 죽는다.** J6 ±120 교정 때
   데이터 33만 프레임을 변환했고, 그 전에 학습한 체크포인트는 전부 재학습
   대상이 됐다. 절대 좌표는 영점 정의에 붙어 있기 때문이다. 변화량은 상수
   오프셋이 빼기에서 사라지므로 액션 쪽은 영점 이동에 면역이다.
2. **클러치 슬립으로 영점이 흘러도** 절대 정책은 낡은 좌표계의 목표를 그대로
   민다. 델타 정책은 "지금 자세에서 이만큼"이라 시각 피드백과 결합하면 흘러간
   좌표계에서도 상대적으로 옳은 동작을 낸다.

부수 이득 둘:

- **정규화 조건이 좋아진다.** 절대 위치는 작업 공간 전체에 퍼지지만 델타는
  0 근처의 좁은 분포다. mean/std 정규화가 훨씬 잘 먹는다.
- **폭주가 유계가 된다.** 절대 정책이 미치면 임의 자세로 점프하지만, 델타
  정책은 한 스텝에 데이터 분포만큼만 움직인다. 여기에 스텝당 클램프를 더하면
  하드 바운드가 된다.

한계도 처음부터 적어 둔다: **관측(observation.state)은 v1에서 절대값 그대로
둔다.** 작업 공간 한계 같은 절대 정보가 필요하고, 이미지가 조건의 주력이다.
따라서 영점 이동 면역은 액션 생성 쪽 이야기지 관측 조건 쪽까지 완전하지는
않다 — 과장하지 않는다.

## 액션 공간 정의

세 가지 후보를 비교했다.

| | 정의 | 오프라인 변환 | 비고 |
|---|---|---|---|
| F1 | `d[t] = a[t] − s[t]` (지령 − 같은 프레임 피드백) | 가능 | 추종 지연을 흡수하지만 **피드백을 믿어야 한다** — 이 하드웨어에서 피드백은 슬립 때 거짓말한다 |
| F2 | 청크 시작 상태 기준 `d[t+i] = a[t+i] − s[t]` | **불가** (청크 시작점이 샘플링 시점에 정해짐 → LeRobot 학습 코드를 패치해야 함) | CLI 래핑 원칙 위반 |
| **F3** | `d[t] = a[t] − a[t−1]` (지령의 차분, 에피소드 첫 프레임은 `a[0] − s[0]`) | 가능 | **액션만 쓴다** — 피드백 오염과 무관, 변환이 프레임 단위로 닫힘 |

**v1은 F3.** 근거: 액션은 리더 지령이라 슬립·마스터 무피드백 문제와 무관하고,
프레임 단위 오프라인 변환으로 닫히므로 **LeRobot 학습 코드를 한 줄도 안
고친다** (CLI 래핑 원칙 유지).

F3의 알려진 트레이드오프: 추론 앵커는 팔의 실측 상태 `s_now`인데 학습 델타는
`a[t−1]` 기준이다. 둘의 차이 = 추종 지연 ε 만큼 지령이 살짝 "뒤"에 붙는다.
변환기가 데이터셋의 `mean |a[t−1] − s[t]|` 를 관절별로 출력하게 해서, ε이
실측으로 크면 그때 F1을 재검토한다 — 추측으로 미리 만들지 않는다.

**그리퍼는 절대값 유지.** 개도(開度)는 절대량이고 델타 누적은 오차만 쌓는다.
관절 6축만 델타, 그리퍼 채널은 변환에서 제외한다(양팔이면 14차원 중 12만).

## 데이터 흐름

### 1. 오프라인 변환기 (신규, 단독 실행 가능)

`python -m piper_delta convert <dataset> [--out <dataset>-delta]`
(`piper_phase` 전례를 따른 단독 모듈. 웹 없이도 돈다.)

- 원본은 건드리지 않고 **사본을 만든다** — J6 ±120 변환과 같은 방식.
- parquet의 action 컬럼만 차분으로 다시 쓴다. episode 경계에서 리셋
  (첫 프레임은 `a[0] − s[0]`).
- stats는 LeRobot이 데이터에서 다시 계산하므로 손댈 것 없음.
- **자체 검증이 변환의 일부다**: 사본에서 cumsum으로 절대를 재구성해 원본과
  1e-3 이내인지 에피소드 전수 확인. 실패하면 사본을 지우고 실패로 끝낸다.
- `meta/piper_notes.json`(기존 사이드카)에 기록:
  `action_space: "delta_v1"`, `delta_dims`(그리퍼 제외 마스크), 원본 데이터셋
  id, 관절별 추종 지연 ε 통계. **LeRobot의 info.json에는 아무것도 심지
  않는다** (사이드카 원칙).

### 2. 학습 — 수정 없음

스톡 ACT CLI를 그대로 쓴다. 변환된 데이터셋을 고르면 끝. 학습이 끝나면
백엔드가 원본 데이터셋의 사이드카에서 `action_space`를 읽어 **체크포인트
사이드카**(`piper_notes.json`)로 복사한다 — 학습 시작 API가 데이터셋 id를
아는 자리가 그 복사의 자리다.

### 3. 추론 — wrapper 훅 하나

`wrapper/lerobot_wrapper.py`의 `_inference_thread_fn`,
`predict_action_chunk()` 직후(현재 538행 부근)가 유일한 수정점이다:

```
chunk_delta = policy.predict_action_chunk(observation)      # (B, k, dim)
chunk_abs   = anchor + cumsum(chunk_delta[..., delta_dims]) # 절대 복원
```

- **앵커 = 그 추론에 넣은 observation.state.** 푸시 시점에 다시 읽지 않는다 —
  모델이 본 상태와 복원 기준이 같아야 한다.
- **복원 → 그 다음에 `_actions_per_chunk` 절단.** 순서가 반대면 잘려 나간
  델타의 변위가 통째로 증발한다. 이 순서는 테스트로 박는다.
- 재앵커 주기 = 청크 리필 주기(기존 refill 로직 그대로). 청크 안에서는
  open-loop 적분, 청크 경계마다 실측 상태로 드리프트를 지운다. 새 청크가
  기존 큐를 통째로 교체하는 현재 구조(552행)와 그대로 맞물린다.
- 스텝당 `MAX_DELTA_DEG` 클램프를 복원 직전에 건다(데이터 분포에서 산정,
  변환기가 p99.9를 사이드카에 기록). robotd의 기구학 필터와
  `max_relative_target`은 그 바깥의 기존 백스톱으로 그대로 둔다.

## 안전 — 마커 체인은 fail-closed

가장 위험한 사고는 파라미터가 아니라 **모드 불일치**다:

| 사고 | 증상 | 방어 |
|---|---|---|
| 델타 체크포인트를 절대 모드로 실행 | 액션 ≈ 0 → 팔이 영점 자세로 **돌진** | 아래 마커 체인 |
| 절대 체크포인트를 델타 모드로 실행 | 현재 상태 + 절대 목표 = 두 배 거리 점프 | 동일 |

체인: 데이터셋 사이드카 → (학습 시작 API가 복사) → 체크포인트 사이드카 →
추론 시작 API가 읽어 wrapper에 `--action-space delta_v1` 전달 → wrapper는
**플래그가 있을 때만** 복원 훅을 켠다. 사이드카가 없는 기존 체크포인트는
전부 절대로 취급되고 동작이 하나도 안 변한다 — 마이그레이션 없음.

체인이 끊긴 채(사이드카 유실 등) 델타 체크포인트가 절대로 실행되는 경우는
소프트웨어가 알 수 없으므로, 운영 수칙으로 막는다: **새 체크포인트 첫 실행은
무부하 자세에서** (기존 수칙 그대로).

## UI / 백엔드

- 데이터셋 페이지: "델타 변환" 버튼 → 변환기를 subprocess로 (exclusivity의
  `dataset_edit` 레인, 기존 편집과 동일). 완료 시 `<이름>-delta` 사본이 목록에
  뜨고 카드에 `delta` 뱃지.
- 모델 카드: 사이드카의 `action_space` 뱃지 표시. 추론 시작 폼은 자동 전달만
  하고 **사람이 고르는 선택지를 만들지 않는다** — 고를 수 있으면 틀릴 수 있다.
- 새 슬라이더·파라미터 없음. SAFE_PARAMS 변경 없음.

## 평가

같은 원본 데이터셋으로 절대/델타 A/B:

1. 변환 검증(재구성 오차, ε 통계)은 변환기가 출력.
2. 동일 조건 학습 후 실기 성공률 — 기존 `/api/eval/log`·`/api/eval/stats`로
   기록, 태그로 두 체크포인트 구분.
3. 부드러움: 실행 중 지령 시계열의 jerk RMS 비교 (wrapper의 debug 기록 활용).
4. **영점 이동 내성 실측**: 의도적으로 J1 영점을 몇 도 틀어 놓고(소프트웨어
   오프셋으로, 실제 굽기 아님) 두 정책의 열화 비교 — 이 기획의 핵심 주장을
   검증하는 실험이다.

## 작업 순서

1. `piper_delta` 변환기 + 재구성 검증 + ε 통계 + 사이드카 (테스트 포함)
2. wrapper 복원 훅 + 클램프 + `--action-space` 플래그 (복원→절단 순서 테스트)
3. 학습/추론 API의 사이드카 복사·전달 체인
4. UI (변환 버튼, 뱃지)
5. A/B 실험 — 여기서 결과가 나빠지면 1~4는 그대로 두고 기본값을 절대로 유지

## 열린 질문

- ε(추종 지연)이 관절별로 몇 도인가 — 변환기 첫 실행이 답한다. 크면 F1 재검토.
- RTC(flow-matching) 경로와의 상호작용 — v1은 ACT 전용. π0 계열은 이미 자체
  델타 관례가 있어 별도 검토.
- 관측 상대화(영점 이동 완전 면역)는 절대 정보 손실과 맞바꾸는 문제라 v1
  범위 밖. A/B의 영점 이동 실험 결과를 보고 판단.
