# ACT-delta — 절대 위치 대신 이동 변화량을 학습한다 (기획)

상태: **◐ 1~4 구현** (2026-10-24) — 변환기·wrapper 복원·판정 체인·화면. 남은 것: 5 A/B 실기, stage 게이트.
구현하면서 기획과 달라진 것 넷은 각 절에 ⚠ 로 적었다 — stats 재계산, 체크포인트 판정 경로, 스텝당 상한 값,
복원↔절단 순서.

## 왜

ACT는 지금 관절의 **절대 위치**를 액션으로 학습한다. 이 저장소에서 그 대가를
이미 두 번 치렀다:

1. **캘리브레이션이 바뀌면 체크포인트가 통째로 죽는다.** J6 ±120 교정 때
   데이터 33만 프레임을 변환했고, 그 전에 학습한 체크포인트는 전부 재학습
   대상이 됐다. 절대 좌표는 영점 정의에 붙어 있기 때문이다. 변화량은 상수
   오프셋이 빼기에서 사라지므로 액션 쪽은 영점 이동에 면역이다.
2. **클러치 슬립으로 영점이 흘러도** 절대 정책은 낡은 좌표계의 목표를 그대로
   민다. 델타 정책은 "지금 자세에서 이만큼"이라 시각 피드백과 결합하면 흘러간
   좌표계에서도 상대적으로 옳은 동작을 낸다.

부수 이득 둘:

- **정규화 조건이 좋아진다.** 절대 위치는 작업 공간 전체에 퍼지지만 델타는
  0 근처의 좁은 분포다. mean/std 정규화가 훨씬 잘 먹는다.
- **폭주가 유계가 된다.** 절대 정책이 미치면 임의 자세로 점프하지만, 델타
  정책은 한 스텝에 데이터 분포만큼만 움직인다. 여기에 스텝당 클램프를 더하면
  하드 바운드가 된다.

한계도 처음부터 적어 둔다: **관측(observation.state)은 v1에서 절대값 그대로
둔다.** 작업 공간 한계 같은 절대 정보가 필요하고, 이미지가 조건의 주력이다.
따라서 영점 이동 면역은 액션 생성 쪽 이야기지 관측 조건 쪽까지 완전하지는
않다 — 과장하지 않는다.

## 액션 공간 정의

세 가지 후보를 비교했다.

| | 정의 | 오프라인 변환 | 비고 |
|---|---|---|---|
| F1 | `d[t] = a[t] − s[t]` (지령 − 같은 프레임 피드백) | 가능 | 추종 지연을 흡수하지만 **피드백을 믿어야 한다** — 이 하드웨어에서 피드백은 슬립 때 거짓말한다 |
| F2 | 청크 시작 상태 기준 `d[t+i] = a[t+i] − s[t]` | **불가** (청크 시작점이 샘플링 시점에 정해짐 → LeRobot 학습 코드를 패치해야 함) | CLI 래핑 원칙 위반 |
| **F3** | `d[t] = a[t] − a[t−1]` (지령의 차분, 에피소드 첫 프레임은 `a[0] − s[0]`) | 가능 | **액션만 쓴다** — 피드백 오염과 무관, 변환이 프레임 단위로 닫힘 |

**v1은 F3.** 근거: 액션은 리더 지령이라 슬립·마스터 무피드백 문제와 무관하고,
프레임 단위 오프라인 변환으로 닫히므로 **LeRobot 학습 코드를 한 줄도 안
고친다** (CLI 래핑 원칙 유지).

F3의 알려진 트레이드오프: 추론 앵커는 팔의 실측 상태 `s_now`인데 학습 델타는
`a[t−1]` 기준이다. 둘의 차이 = 추종 지연 ε 만큼 지령이 살짝 "뒤"에 붙는다.
변환기가 데이터셋의 `mean |a[t−1] − s[t]|` 를 관절별로 출력하게 해서, ε이
실측으로 크면 그때 F1을 재검토한다 — 추측으로 미리 만들지 않는다.

**그리퍼는 절대값 유지.** 개도(開度)는 절대량이고 델타 누적은 오차만 쌓는다.
관절 6축만 델타, 그리퍼 채널은 변환에서 제외한다(양팔이면 14차원 중 12만).

## 데이터 흐름

### 1. 오프라인 변환기 — `python -m lerobot_policy_piper.delta <dataset>`

[custom_policies/lerobot_policy_piper/delta.py](../custom_policies/lerobot_policy_piper/delta.py). 굽기(`bake.py`)
옆에 둔다 — 둘 다 lerobot 의 통계 함수를 쓰는 "학습용 사본 만들기" 이고, 설치 패키지를 하나 더 늘리지 않는다.

- 원본은 건드리지 않고 **LeRobot 캐시에 `<org>/<이름>_delta` 사본**을 만든다(`_stage` 와 같은 꼴) — 원본이 HF 허브
  캐시에 있어도 그 옆이 아니다(`bake.default_output`). 비디오는 실제 파일에 하드링크.
- 관절 채널만 차분, 에피소드 첫 프레임은 `a[0] − s[0]`, 그리퍼는 절대. 채널은 info.json 의 **이름**으로
  고른다(`gripper` 가 든 것 제외) — 양팔이면 14 중 12.
- ⚠ **stats 를 다시 쓴다** (기획엔 "LeRobot 이 다시 계산하므로 손댈 것 없음" 이었는데 사실이 아니다).
  LeRobot 은 정규화 통계를 `meta/stats.json` 에서 **읽기만** 한다. 그대로 두면 델타(0 근처, 몇 도)를 절대
  위치 통계(수십 도)로 정규화한다. 그래서 `stats.json` 과 `meta/episodes` 의 `stats/action/*` 를 새로 계산한다.
- **자체 검증**: 저장한 float32 델타를 누적해 절대를 되만들고 원본과 에피소드 전수 1e-3° 이내인지 본다 +
  LeRobot 로더로 열어 델타·델타 통계가 나오는지 본다. 실패하면 사본을 지운다.
  실측(`min_cube_071410`, 31,349 프레임): 최대 오차 7.5e-7°.
- 근거 메타 `meta/piper_delta.json`: `action_space: delta_v1`, `delta_names`/`absolute_names`, 스텝당 상한
  `clamp`, `step_p999`, 첫 프레임 최대치, 관절별 추종 지연 ε(평균·p95), 원본 id. LeRobot 의 info.json 에는
  아무것도 심지 않는다.
- 거절: 이미 델타 / 구운 사본(`_stage`) — **순서는 델타 → 굽기.** 굽기가 `meta/` 를 통째로 옮기므로 이 표식도
  따라가 `<이름>_delta_stage` 도 델타로 읽힌다. 페이즈 분석은 액션의 그리퍼 채널만 읽고 그리퍼는 절대
  그대로라, 델타 사본에서도 분석·굽기가 맞다.

### 2. 학습 — 수정 없음

스톡 ACT CLI 그대로, 변환된 데이터셋을 고르면 끝 (실측: `--policy.type=act` 600 스텝, loss 5.7→2.3).
⚠ 기획의 "학습이 끝나면 체크포인트로 복사" 는 하지 않는다 — 아래 3의 판정이 대신한다.

### 3. 추론 — 판정은 백엔드, 복원은 wrapper

**판정** ([backend/app/services/action_space.py](../backend/app/services/action_space.py)) — 사람이 고르지 않는다:

1. 체크포인트 폴더의 표식 `piper_action_space.json`
2. ⚠ LeRobot 이 **체크포인트마다** 남기는 `train_config.json` 의 데이터셋 → 그 데이터셋의 `meta/piper_delta.json`.
   기획의 "학습 종료 시 복사" 보다 낫다 — 학습 **도중** 체크포인트도, 원격에서 학습해 받은 것도 같은 길이고,
   학습 시작 전엔 `output_dir` 이 없어야 해서(LeRobot 규칙) 미리 쓸 자리도 없다.
3. 데이터셋을 못 찾았는데 이름이 `_delta` 면 **`unknown` — 추론을 막는다.** 아니면 절대(기존 체크포인트 전부).
4. `train_config.json` 이 없으면(허브 모델) 절대.

델타면 추론 시작이 `--action-space delta_v1 --delta-spec {채널, 상한}` 을 싣고, **시작할 때** 1의 표식을 남긴다
(미리보기는 파일을 안 고친다, HF 캐시 스냅샷에는 안 쓴다). 그 뒤로는 데이터셋이 지워져도 델타다. 절대면 아무
플래그도 안 붙어 기존 명령이 한 글자도 안 바뀐다. 정책 서버(gRPC) 모드는 델타면 거절 — 되돌리는 것은 로컬 wrapper 다.

**복원** ([wrapper/delta_action.py](../wrapper/delta_action.py)) — `predict_action_chunk` → 역정규화 → 복원 → 큐/앙상블:

```
절대[i] = 앵커 + Σ_{j≤i} clip(d[j], ±상한)        (관절 채널만, 그리퍼는 그대로)
```

- **앵커 = 그 추론에 넣은 관측의 state** (채널 이름으로). 큐에 넣을 때 다시 읽지 않는다.
- ⚠ **복원과 `_actions_per_chunk` 절단의 순서는 결과를 안 바꾼다.** 기획은 "복원 → 절단" 을 못박았지만, 앞에서부터
  자르고 누적합은 앞쪽 항만 보므로 같다. wrapper 는 자른 뒤 되돌린다 — 테스트가 이 성질을 잡는다.
- ⚠ **스텝당 상한 = 데모에서 실제로 나온 가장 큰 한 스텝**(첫 프레임 제외). 기획의 p99.9 로 자르면 데모에 실제로
  있던 빠른 동작이 느려진다 — 데모 밖의 속도만 자른다. p99.9 는 참고로 사이드카에 남는다.
- 시간 앙상블과 그대로 맞물린다 — 청크마다 절대로 되돌린 뒤 평균하므로.
- 실측(하네스: 실제 wrapper 루프 + 가짜 로봇 + 600스텝 델타 ACT): 첫 청크 60스텝의 목표가 따로 계산한 복원과
  0.005° 이내(델타를 그대로 보냈다면 100°), 395스텝 중 영점 근처로 간 스텝 0.

## 대기 구간 드리프트 — 이 기획의 가장 약한 지점

델타 액션은 정지 자세에 **복원력이 없다.** 발산은 두 층에서 생긴다:

1. **청크 안** — 복원이 `anchor + cumsum` 이라 예측 오차가 스텝마다 적분된다.
   대기 구간의 참값이 전부 0이어도, 스텝당 0.005° 의 편향이면 100스텝 청크
   끝에서 0.5° 다. `MAX_DELTA_DEG` 클램프는 못 막는다 — 드리프트는 클램프보다
   한참 느리다.
2. **청크 간 — 더 근본적이다.** 재앵커가 지우는 것은 "명령 적분기 vs 실측"의
   불일치다. 대기 중 청크가 팔을 ε 만큼 밀면 팔이 실제로 ε 이동하고, 다음
   재앵커는 **흘러간 그 자리**를 새 기준으로 삼는다 — 앵커가 드리프트를
   따라간다. 절대 액션에서 정지 자세는 복원력 있는 고정점이지만, 델타에서는
   marginal fixed point 라 대기 위치가 시간에 비례해 걸어간다. ACT 원 논문도
   델타를 시험했다가 절대가 낫다고 보고했고, 이런 누적 오차가 지목된 이유 중
   하나다. (그리퍼는 절대 유지라 이 문제 밖이다.)

### 방어 — act_s stage 로 실행기를 게이트한다

delta 는 데이터셋 변환 + wrapper 훅이고 [act-s](act-s.md)는 정책 타입이라
**서로 다른 층이다** — delta 변환한 데이터셋에 subtask 를 굽고 `act_s` 로
학습하면 그대로 합쳐지고, wrapper 에서 `last_aux` 를 읽는 자리와 delta 를
복원하는 자리가 같다. stage 로 실행기를 얼리는 것은 act-s §9 가 금지한
"stage 를 관측에 되먹임"이 아니라 허용한 **출력으로 감시** 쪽이다.

⚠ **stage 단독 게이트는 교착이 된다.** 에피소드 시작 장면에서 stage 는
IDLE 인데 액션 청크는 "이제 출발"하는 변위를 담고 있다(청크가 세그먼트
경계를 넘는다). IDLE 이라고 얼리면 팔이 출발을 못 하고, 장면이 안 바뀌니
stage 도 IDLE 에 머문다. 그래서 AND 게이트다:

> 얼림(청크 전체를 0으로 스냅) =
> stage ∈ 정지 단계 {IDLE, DONE} **AND** 청크의 관절별 순변위 < θ,
> stage 판정은 act-s §3.4 히스테리시스(`stage_p>0.8 and margin>0.5`) 그대로

- 출발 청크는 순변위가 커서 게이트를 통과한다 — 교착 없음.
- 변위 데드밴드 단독의 걱정이었던 "느린 미세 동작 사장"도 풀린다 —
  ALIGN·GRASP 은 게이트 대상이 아니다.
- 오분류가 비대칭으로 안전하다: 잘못 얼리면 팔이 멈출 뿐이고, 못 얼리면
  지금 상태 그대로다.

한계 둘: **HOLD 는 대기가 아니라 운반이라**(실측 라벨 분포 12,690프레임)
게이트 못 건다 — HOLD 중 잠깐 정지하는 구간은 미커버. 그리고 이 방어는
act_s 체크포인트에서만 작동한다. 바닐라 ACT delta 의 폴백은 드리프트
실측(아래 평가 5) + 변위 데드밴드 단독인데, 데드밴드 단독은 변환기가 뽑는
"대기 구간 델타 노이즈 바닥 vs 가장 느린 실제 동작의 청크 변위" 분포에
틈이 있을 때만 쓸 수 있다 — 겹치면 못 쓴다.

## 안전 — 모드 불일치는 fail-closed

가장 위험한 사고는 파라미터가 아니라 **모드 불일치**다:

| 사고 | 증상 | 방어 |
|---|---|---|
| 델타 체크포인트를 절대 모드로 실행 | 액션 ≈ 0 → 팔이 영점 자세로 **돌진** | 판정이 자동으로 플래그를 싣는다 · 이름 가드(`unknown` → 거절) · 표식 |
| 절대 체크포인트를 델타 모드로 실행 | 현재 상태 + 절대 목표 = 두 배 거리 점프 | 동일 |
| CLI 직접 편집으로 플래그를 지우거나 바꿈 | 위 둘 중 하나 | 백엔드가 시작 전에 판정과 대조해 거절, wrapper 도 **로봇을 만들기 전에** 표식과 대조해 거절 (실측) |
| 델타 채널 이름이 로봇에 없음(다른 로봇·양팔) | 엉뚱한 관절에 더함 | wrapper 가 시작 시 거절 |

남는 구멍: 표식이 생기기 전에(한 번도 추론 안 한 채) 학습 데이터셋이 지워지고, 그 이름도 `_delta` 가 아니면
절대로 판정된다. 변환기가 늘 `_delta` 로 만들므로 이름을 손으로 바꾼 경우뿐이다 — 운영 수칙은 그대로:
**새 체크포인트 첫 실행은 무부하 자세에서.**

## UI / 백엔드

- 데이터셋 상세: **[델타 변환]** → `POST /api/datasets/{id}/delta` → 데이터셋 편집 유닛(`piper-xfer-edit`,
  exclusivity `dataset_edit` 레인). 화면은 `/edit-status` 로 끝을 기다리고 **사본이 목록에 델타로 떴는지로**
  성공을 판정한다("안 돌고 있음" 은 성공이 아니다). 실패하면 유닛의 마지막 로그 줄을 보여 준다.
- 표시: 데이터셋 카드·상세(`Δ 델타 사본`), 학습·에피소드 화면의 데이터셋 목록, 모델 카드·상세(`Δ`, 모름은
  `Δ?`), 추론 화면의 모델 요구사항(로컬이면 "되돌린다", 서버 모드면 "못 돈다").
- 추론 시작 폼에는 **고르는 선택지가 없다** — 고를 수 있으면 틀릴 수 있다. 새 슬라이더·파라미터 없음.

## 평가

같은 원본 데이터셋으로 절대/델타 A/B:

1. 변환 검증(재구성 오차, ε 통계)은 변환기가 출력.
2. 동일 조건 학습 후 실기 성공률 — 기존 `/api/eval/log`·`/api/eval/stats`로
   기록, 태그로 두 체크포인트 구분.
3. 부드러움: 실행 중 지령 시계열의 jerk RMS 비교 (wrapper의 debug 기록 활용).
4. **영점 이동 내성 실측**: 의도적으로 J1 영점을 몇 도 틀어 놓고(소프트웨어
   오프셋으로, 실제 굽기 아님) 두 정책의 열화 비교 — 이 기획의 핵심 주장을
   검증하는 실험이다.
5. **대기 구간 드리프트 실측**: 대기가 긴 에피소드에서 30~60초 정지 유지 시
   관절 드리프트를 절대/델타(게이트 유/무)로 비교. 학습 데이터의 대기 구간은
   델타가 정확히 0이라 모델이 정적 장면에서 강한 0-끌림을 배울 가능성도
   있다 — 실제 심각도는 여기서 정해진다.

## 작업 순서

1. ☑ 변환기 + 재구성 검증 + ε 통계 + 사이드카 — `custom_policies/tests/test_delta.py`
2. ☑ wrapper 복원 훅 + 상한 + `--action-space` 플래그 — `backend/tests/test_delta_actions.py`
3. ☑ 판정 체인 (`train_config.json` → 데이터셋 사이드카 → 체크포인트 표식)
4. ☑ UI (변환 버튼, 배지)
5. A/B 실험 — 여기서 결과가 나빠지면 1~4는 그대로 두고 기본값을 절대로 유지

## 열린 질문

- ε(추종 지연)이 관절별로 몇 도인가 — 첫 실측(`min_cube_071410`): 평균 J1 0.11° · J2 0.63° · J3 0.98° ·
  J4 0.17° · J5 0.69° · J6 0.14°. 스텝당 델타(데모 최대 3~18°)에 비해 작다 — F1 재검토는 A/B 결과를 본 뒤.
- 대기 드리프트가 게이트 없이도 무시할 수준인가 — 평가 5가 답한다. 심하면
  F2(청크 내 적분이 없는 앵커 기준 변위) 재평가가 다음 카드다: 노이즈 적분
  한 층이 사라지지만 학습 코드 패치와 맞바꿔야 한다.
- RTC(flow-matching) 경로와의 상호작용 — v1은 ACT 전용. π0 계열은 이미 자체
  델타 관례가 있어 별도 검토.
- 관측 상대화(영점 이동 완전 면역)는 절대 정보 손실과 맞바꾸는 문제라 v1
  범위 밖. A/B의 영점 이동 실험 결과를 보고 판단.
