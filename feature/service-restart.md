# 서비스 재시작 — "고쳤는데 왜 안 되지"를 없앤다

## 1. 왜

**유닛은 기동 시점의 코드로 돈다.** 파일을 고쳐도 재시작 전에는 아무 일도 안
일어나는데, 그 사실이 화면 어디에도 없었다. 이 저장소가 그걸로 두 번 크게 헤맸다:

- **rsd 가 이틀 전 코드로 돌았다** — 고친 깊이 단위 버그(D405 10배)가 그대로
  재현돼, 코드를 다시 의심하며 한참을 썼다. 커밋 08-22 17:05 vs 유닛 기동 08-20 13:50
- **게이트웨이가 새 라우트를 몰랐다** — `/devices/summary`, `/background-mask` 가
  404 였다. 코드에는 분명히 있었다

둘 다 **기계가 답할 수 있는 질문**이다: 지금 도는 것보다 새 코드가 있는가?

## 2. 판정 — 유닛 기동 시각 vs 그 유닛이 읽는 소스

```
stale = (소스 최신 수정 시각) > (유닛 기동 시각) + 여유
```

**전부를 보지 않는다.** 프론트엔드를 고쳤다고 robotd 가 낡았다고 하면 경고가 늘
켜져 있어 아무도 안 본다. 데몬이 실제로 import 하는 것만 본다:

| 유닛 | 보는 소스 |
|---|---|
| `piper-rsd` | `daemons/rsd.py` · `rs` · `cam` · `shm` · `bus` |
| `piper-camerad` | `daemons/camerad.py` · `cam` · `shm` · `bus` |
| `piper-robotd` | `daemons/robotd.py` · `robot` · `shm` · `bus` |
| `piper-estopd` | `daemons/estopd.py` · `bus` |
| 게이트웨이 | `backend/app` · `wrapper` · `bus` · `shm` |

> ⚠ **우리 소스를 아는 유닛만 판정한다.** `piper-ollama` 처럼 남의 서비스를 감싼
> 유닛까지 "낡았다"고 하면 경고가 상시등이 된다.

> ⚠ **`__pycache__` 는 소스가 아니다.** import 만 해도 갱신돼 늘 낡은 것처럼 보인다.

> ⚠ **몇 초의 여유를 둔다.** 배포는 파일을 쓰고 몇 초 뒤 유닛을 띄운다. 그 순서를
> "낡았다"로 읽으면 **배포 직후마다** 거짓 경고가 뜬다.

## 3. 재시작

유닛은 `systemctl --user restart`. **`piper-` 접두사만** 받는다 — 웹에서 남의
서비스를 재시작하는 창구가 되면 안 된다.

**추론·녹화 중에는 막는다.** rsd 를 재시작하면 카메라 스트림이 끊기고 robotd 면
팔 상태 발행이 멈춘다 — 돌고 있는 에피소드가 그대로 깨진다.

### 게이트웨이는 자기 자신을 갈아입는다

감독자가 없으므로(여기서는 detached uvicorn) `os.execv` 로 **같은 명령줄을 다시
실행**한다. 새 프로세스가 뜨는 게 아니라 이 프로세스가 이미지를 갈아끼우는 것이라
**PID 가 유지된다** — 로그가 그대로 보여준다:

```
게이트웨이 재시작: execv [python, -m, uvicorn, app.main:app, --host, 0.0.0.0, --port, 8000]
INFO:     Started server process [1982517]
INFO:     Application startup complete.
```

> ⚠ **응답을 보낸 뒤에** 갈아탄다. 먼저 죽으면 브라우저는 "요청 실패"만 보고,
> 재시작이 된 건지 터진 건지 알 수 없다.

> ⚠ **`sys.argv` 를 쓰면 안 된다.** `python -m uvicorn` 으로 뜬 경우 `sys.argv[0]` 은
> `site-packages/uvicorn/__main__.py` 인데, 그 파일을 직접 실행하면 그 디렉토리가
> `sys.path[0]` 이 되어 `uvicorn/logging.py` 가 표준 `logging` 을 가린다.
> 실기에서 이렇게 죽었다:
>
> ```
> AttributeError: module 'logging' has no attribute 'Formatter'
> ```
>
> `sys.orig_argv` 가 `-m uvicorn` 을 담은 원래 명령줄이다. 그것도 못 만들면
> **재시작 버튼을 아예 비활성화한다** — 죽기만 하고 안 돌아오는 게 최악이다.

## 4. 화면

설정 페이지를 탭으로 나눴다 (`일반` / `서비스`). 탭 목록은 한 곳에서 나온다 —
`pages.ts` 가 페이지에 대해 하는 일과 같다.

서비스 탭은 유닛마다 한 줄이고, **낡은 것은 노란 테두리**로 뜬다. 위쪽에 몇 개가
낡았는지 한 줄로 요약한다.

## 5. 아직 안 한 것

- **원격(.120) 서비스** — 지금은 이 기계만. 배포 대상의 유닛 상태를 같은 화면에서
  보려면 외부 API 를 타야 한다
- **컨테이너 배포** — `.120` 은 docker 라 `systemctl` 이 아니라 `docker restart` 다.
  판정(낡음)은 같은 방식이 되지만 재시작 경로가 다르다
- **git 커밋 기준 판정** — 지금은 파일 mtime 이라 `git checkout` 으로 되돌려도
  "새것"으로 보인다. 실무상 문제는 없었지만 정확하진 않다
