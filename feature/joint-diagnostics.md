# 관절 검사 — 움직이면서 재고, 관절끼리 견준다

로봇 페이지 **검사** 탭. 관절을 정해진 모션으로 움직이며 전 항목을 로그하고,
관절끼리 비교해 **혼자 다른 놈**을 찾는다.

## 왜

지금 화면은 *지금 값*만 보여준다. 그런데 관절 이상은 **부하가 걸릴 때** 드러난다 —
can2 의 joint2 가 `과전류·드라이버 오류` 플래그를 세운 것도 가만히 있을 때가
아니었다. 정지 상태의 전압·온도로는 못 잡는다.

절대 기준은 없다. 대신 **같은 팔의 여섯 관절이 같은 모션을 했을 때** 하나만
추종 오차가 크거나 전류가 높으면 그게 답이다. 관절끼리가 서로의 대조군이다.

## 기록 항목 (관절마다)

| 열 | 출처 | 단위 |
|---|---|---|
| `feedback_deg` | `GetArmJointMsgs` | ° |
| `ctrl_deg` | `GetArmJointCtrl` | ° |
| `ctrl_minus_feedback_deg` | 파생 — **추종 오차** | ° |
| `motor_speed_rad_s` · `motor_current_a` · `motor_pos_rad` · `effort_nm` | `GetArmHighSpdInfoMsgs` (0x251~6) | |
| `driver_voltage_v` · `bus_current_a` · `foc_temp_c` · `motor_temp_c` | `GetArmLowSpdInfoMsgs` (0x261~6) | |
| `driver_overcurrent` · `stall` · `driver_error` · `collision` · `enabled` | `foc_status` 플래그 | |
| `angle_limit` · `comm_error` | 팔 상태(0x2A1) 비트 | |

## 모션

⚠ **작고 느리게.** 진단이 사고의 원인이 되면 안 된다.

- 지금 자세를 중심으로 한 **사인파**. 진폭은 `min(10°, 그 관절 가동범위의 12%)`
  이고, 양끝에서 설정 한계에 **5° 여유**를 남기도록 다시 줄인다
- 주기 4초 × 2회. 가감속이 완만해 관성 충격이 없다
- **개별**: 고른 관절만 움직이고 나머지는 지금 자세를 유지한다
- **전체**: 여섯을 동시에, 다만 **위상을 60°씩 어긋나게** 한다 — 한꺼번에
  같은 방향으로 최대 속도를 내면 팔 전체가 크게 흔들린다

## 안전

- 추론·녹화·텔레옵 중이면 거절 (`/zero` 와 같은 판단)
- **마스터 팔은 거절** — 외부 명령을 무시하므로 "안 움직였다"가 곧 고장으로
  오독된다
- 명령은 robotd 의 `filter_goal` 을 탄다 (바닥·범위·변화율·데드맨)
- 시작 전에 화면이 **무엇이 얼마나 움직이는지** 숫자로 말하고 확인을 받는다
- 언제든 중지. 중지하면 그 자리에 선다(토크를 끊지 않는다 — 끊으면 떨어진다)

## 분석

관절별 요약: 추종 오차(최대·RMS), 전류(최대·평균), 토크 최대, 온도 상승,
플래그가 선 적 있는지. 그리고 **여섯 중 튀는 놈**을 표시한다 — 중앙값 대비
2배 넘는 항목에 색을 준다.

⚠ 판정을 내리지 않는다. "joint2 가 고장" 이 아니라 "joint2 의 추종 오차가
다른 관절의 3.4배" 라고 쓴다. 원인은 사람이 본다.

## 범위 밖

- 절대 합격/불합격 기준 — 우리에겐 그 데이터가 없다
- 자동 보정 — 재기만 한다
