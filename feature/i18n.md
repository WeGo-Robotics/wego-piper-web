# 다국어 (i18n)

화면 언어를 고를 수 있다. 원문은 한국어이고, 영어가 첫 번역이다. **일본어·중국어 등은
`locales/<코드>.json` 파일 하나를 놓으면 된다** — 코드를 고치지 않는다.

## 한눈에

```
 코드의 한국어 원문 ─┬─ 프론트  t('로봇 등록')        ┐
                     │   tools/i18n.py ← i18n-extract.mjs (TS 구문 트리)
 백엔드·데몬의 한국어 ─┴─ 파이썬  f"{cam_id} 가 …"       ┤→ 키(원문) 목록
   문장 (그대로 둔다)        tools/i18n.py (AST)         ┘
                                                         │
          frontend/src/i18n/locales/en.json  ←── { "로봇 등록": "Register robot", … }
                    ja.json · zh.json …  (파일 = 언어)

 브라우저:  t(원문) → 번역 | 없으면 원문      tb(백엔드 문장) → 키의 "모양"에 맞춰 번역
```

## 결정 몇 가지와 이유

**키는 한국어 원문이다.** `t('로봇 등록')` 의 인자가 곧 키다.
- 이 코드베이스는 이미 한국어로 쓰여 있다(2,600여 문장). 의미 키(`robots.add.title`)를
  지으려면 문장마다 이름을 짓고 두 곳을 오가야 하고, 코드를 읽으면 화면에 뭐가 나가는지
  안 보인다.
- **번역이 빠져도 화면이 비지 않는다** — 한국어가 그대로 보인다. 빈 칸·키 이름이 화면에
  뜨는 사고가 없다.
- 대가: 원문을 고치면 키가 바뀌어 번역이 낡는다. `tools/i18n.py check` / 테스트가 잡는다.
  같은 한국어가 문맥에 따라 영어로 다르게 옮겨져야 하면 한국어 쪽을 구분해 적는다
  (화면에 보이는 글자가 곧 구분자다). 한국어를 못 바꾸면 **문맥**을 준다 —
  `t('정렬', undefined, 'sort')` 의 키는 `sort::정렬` 이다. 짧은 단어(`정렬`·`해제`·`조작`)가
  자주 걸린다.

**백엔드는 한국어 문장을 그대로 만든다.** 문장마다 코드를 붙이지 않는다.
게이트웨이만이 아니라 `robotd`·`camerad`·`rsd` 같은 데몬도 화면에 나가는 문장을 만들고,
그 패키지들이 서로 다른 릴리스 단위라 공유 번역 모듈을 두기 어렵다. 대신 **프론트가
받은 문장을 키의 모양에 맞춘다**: `f"{cam_id} 가 연결돼 있지 않습니다"` 는 키
`{cam_id} 가 연결돼 있지 않습니다` 가 되고, 받은 `cam3 가 연결돼 있지 않습니다` 는 그
패턴에 맞아 `cam3 is not connected` 가 된다. 못 맞추면 한국어 원문이 그대로 보인다.

**언어를 바꿔도 화면을 새로 띄우지 않는다.** 새로고침·루트 재마운트는 WS 를 끊고, 그
틈에 E-stop heartbeat 가 2초를 넘기면 **녹화·추론이 SIGKILL 된다**(CLAUDE.md 안전
주의). 바뀐 언어는 `useT()` 를 쓴 컴포넌트만 다시 그린다.

**브라우저 언어로 자동 전환하지 않는다.** 기본은 한국어, 사용자가 고른 것만 이 브라우저에
저장된다(`localStorage['piper.lang']`). 릴리스를 받는 순간 현장 PC 의 언어가 바뀌면 안
된다. 맨 위 상태바와 로그인 화면에 언어 선택이 있어 한국어를 못 읽어도 찾을 수 있다.

## 쓰는 법 (프론트)

| 상황 | 쓰는 것 | 예 |
|---|---|---|
| 컴포넌트 안 | `const t = useT()` | `{t('로봇 등록')}` · `t('에피소드 {n}개', { n })` |
| JSX 를 문장 속에 | `t.rich` | `t.rich('{link} 를 확인하세요', { link: <a …>문서</a> })` |
| 컴포넌트 밖(서비스·헬퍼) | `tr` | `tr('응답 없음')` — **부른 순간**의 언어 |
| 모듈 상수(표·옵션 목록) | `msg` 로 표시하고 **그릴 때** `t(x)` | `{ label: msg('약하게') }` → `{t(opt.label)}` |
| 백엔드가 보낸 문장 | 이미 옮겨져 온다(`api`·WS 길목) | 직접 필요하면 `tb(text)` |
| 날짜·숫자 | `fmt.number` · `fmt.dateTime` … | `toLocaleString('ko-KR')` 을 직접 쓰지 않는다 |
| 같은 한국어, 다른 뜻 | 세 번째 인자 `ctx` | `t('정렬', undefined, 'sort')` → 번역 키 `sort::정렬` (없으면 `정렬` 로 내려간다) |

규칙:
- **`useT()` 의 `t` 를 쓴다** — 그래야 언어가 바뀔 때 다시 그려진다. `tr` 는 그릴 때마다
  다시 불리는 자리(렌더 중 호출되는 헬퍼)나 이벤트 핸들러에서만 쓴다.
- `t` 를 쓴 `useCallback`/`useMemo`/`useEffect` 의 의존성에 `t` 를 넣는다
  (`react-hooks/exhaustive-deps` 가 알려 준다). `t` 는 언어가 바뀔 때만 달라진다.
- 컴포넌트 안에 `t`·`tr`·`msg` 라는 이름의 지역 변수를 두지 않는다(번역 함수를 가린다).
  `.map((t) => …)` 대신 `(tab) => …`.
- **인자 이름은 읽히게**: `{n}` · `{name}` · `{cam_id}`. 번역자가 이 이름을 본다.
- 첫 인자는 **리터럴**이어야 추출된다. 변수를 넘기는 `t(label)` 은 그 변수의 원문을
  `msg('…')` 로 표시해 둔 경우에만 번역 대상이 된다.
- 복수형은 번역 파일에서 `{ "one": "{n} episode", "other": "{n} episodes" }` 로 준다.
  개수는 `count` 인자, 없으면 **첫 숫자 인자**다. 코드는 그대로다.
- 사용자 데이터(데이터셋 이름·작업 설명·로봇 별칭)는 번역하지 않는다 — `tb` 도 걸지 않는다.

## 번역하지 않는 것

- 프로세스 로그 스트림(`log`·`train_log` 등)과 LeRobot CLI 출력 — 도구 출력이다
- `console.*` 진단 — 개발자가 검색해야 한다
- `/api/ext/v1` 외부 제어 API 의 응답 문장 — 외부 시스템과의 계약이다
- 서버 로그(`logger.*`)·CLI 도움말(`argparse`)·docstring

## 백엔드 문장을 쓸 때

그냥 한국어로 쓰면 된다. 다만 **정적으로 읽혀야** 번역 대상이 된다:

- 되는 것: 문자열 리터럴, f-string, `"…" + x + "…"`, `"…%s" % x`, `"…{}".format(x)`
- 안 되는 것: 변수에 담았다가 다른 곳에서 조립하는 문장, `join` 으로 만든 문장.
  이런 것은 화면에 한국어로 남는다.
- 문장이 **응답 JSON 의 어느 키**에 담기는지도 본다. 프론트의 `tbDeep`(`i18n/index.ts`
  `TEXT_KEYS`)이 `error`·`warning`·`usb_warning`·`hint`·`reason`·`why`·`message`·`detail`·
  `note`·`text`·`help`·`summary`·`status_text` 의 값만 옮긴다. 새 키가 필요하면 거기에
  더한다. **사용자 데이터가 담기는 키(`name`·`label`·`task`·`description`)는 넣지 않는다.**
- 응답 문구를 코드로 분기하지 않는다 — 번역되면 문구가 바뀐다(`EpisodesPage` 의
  `EditUnitError` 가 그 예).

## 언어 추가

```bash
python tools/i18n.py add ja          # frontend/src/i18n/locales/ja.json 생성 (모든 키, 빈 값)
python tools/i18n.py todo ja --limit 200 > /tmp/ja-part1.json   # 번역할 것 (원문 → "")
# 값을 채운다 — 자리표시자 {name} 은 그대로. 복수형은 {"one":…, "other":…}
python tools/i18n.py check --lang ja # 자리표시자·구조 검증 (선택 언어는 빠진 것만 보고)
```

그게 전부다. 선택 목록은 `locales/*.json` 에서 나오고 이름은 `Intl.DisplayNames` 가
그 언어 자신의 글자로 만든다(`日本語`). 번들에는 고른 언어 파일 하나만 실린다.

- 번역이 비어 있는 문장은 **영어**로, 그것도 없으면 한국어로 내려간다
  (`index.ts` 의 `layersFor`). 일본어 화면에 번역 안 된 문장이 한국어보다 영어로 뜬다.
- `zh-Hant` 처럼 지역·문자 변형은 `zh-Hant.json` 으로 둔다. 변형에 없는 문장은 기본
  `zh.json` 으로 내려간다.
- 필수 언어는 `tools/i18n.py` 의 `REQUIRED` 다(지금은 `en`). 필수 언어는 빠진 번역이
  있으면 테스트가 깨진다. 새 언어를 필수로 올릴 때만 거기에 더한다.

## 문장을 더하거나 고칠 때

1. 코드에 한국어로 쓴다(`t('…')`, 백엔드는 그냥 문장).
2. `python tools/i18n.py sync` — 모든 번역 파일에 빈 칸이 생긴다.
3. 영어를 채운다(필수). 다른 언어는 비워 둬도 영어로 내려간다.
4. `python tools/i18n.py check` 또는 `pytest backend/tests/test_i18n.py`.

원문을 고치면 옛 키가 낡은 키로 남는다. `sync --prune` 이 지운다 — 옛 번역을 새 키로
옮겨 적은 뒤에.

## 도구와 테스트

| 무엇 | 어디 |
|---|---|
| 번역 로직(치환·복수형·문장 맞춤) | `frontend/src/i18n/core.ts` |
| 상태·훅·`tb`·`fmt` | `frontend/src/i18n/index.ts` |
| 언어 선택 UI | `components/LanguageSwitcher.tsx` (맨 위 상태바 · 로그인 화면) |
| 프론트 문장 추출(TS 구문 트리) | `frontend/scripts/i18n-extract.mjs` |
| 파이썬 문장 추출·`status`·`check`·`sync`·`add`·`todo` | `tools/i18n.py` |
| 계약 테스트 | `backend/tests/test_i18n.py` |

## 알려진 한계

- 영어는 한국어보다 길다 — 좁은 버튼·표 머리글에서 줄바꿈이나 잘림이 날 수 있다. 번역을
  짧게 쓰는 것이 1차 대응이고, 화면에서 확인이 필요하다.
- 백엔드 문장의 **인자 값**은 옮기지 않는다(`{state}` 가 한국어 단어면 영어 문장 속에
  한국어가 섞인다). 인자가 상태 단어인 문장은 코드 쪽에서 코드값을 싣는 것이 정답이다.
- 한국어 문장을 정적으로 읽을 수 없는 백엔드 코드(조립해서 만드는 문장)는 번역되지 않는다.
- 사용자가 고르는 언어는 **브라우저마다**다(서버에 저장하지 않는다). 같은 브라우저의
  다른 탭·조종 창은 `storage` 이벤트로 따라간다.
