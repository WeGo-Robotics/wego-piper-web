# 스트림 이름 기준 카메라 — 등록한 카메라는 이름 붙은 shm 스트림으로 받아간다

> 상태: **◐ 1·2·3·4·5·6·7단계 구현됨 (2026-10-15).** 사용자가 붙인 이름이 세그먼트 파일 이름이
> 되고(`/dev/shm/piper.cam.top`), 읽는 곳이 없는 카메라를 일정 시간 뒤 닫는 옵션(끔이 기본)이
> 있다. **남은 것: 스캔 썸네일(§7 2단계 끝 — 실기를 보면서) · D405 와 수집·추론 한 바퀴의 실기.**
> 데몬(camerad·rsd·simd)을 **재시작해야** 반영된다 — 안 하면 옛 규칙 이름으로 발행되고
> 유휴 종료는 안 닫힌다(저장은 되고 화면이 경고한다). 열린 질문 없음.

## 1. 왜

수집·추론이 카메라를 **장치 id**(`/dev/video0`, `rs:250122070363:color`)로 지정하고,
소비 직전에 `segment_for_camera()` 가 그걸 세그먼트 이름으로 바꾼다. 같은 저장소의 다른
소비자(검출·스냅샷·조명 감시)는 이미 **스트림 이름**으로 말한다. 수집·추론만 어휘가 다르다.

그리고 그 이름은 장치 id 의 문자열 변환이라 `/dev/videoN` 이 재열거되면 같이 바뀐다 —
저장된 매핑이 조용히 다른 카메라를 가리킨다.

## 3. 확정한 결정

1. **스트림 이름은 사용자가 바꿀 수 있다.** 기본값은 장치 이름 + 번호 (`HD_Webcam_1`,
   `D435_Color_1`).
2. **선택기**: 등록되고 **연결된** 스트림은 보이고 고를 수 있다. 등록됐지만 **연결 안 된**
   것은 보이되 비활성이다.
3. **등록된 카메라는 웹이든 로봇이든 shm 스트림으로 받아간다.** 스캔 때는 아직 등록 전이라
   **직접 연결해 미리보기 사진만** 받아 온다.
4. **유휴 자동 종료 옵션** — 읽어가는 곳이 없으면 일정 시간 뒤 스트림을 닫는다.
5. **별칭(`label`)과 스트림 이름을 하나로 합친다. 영문만 쓴다.** 사용자가 고치는 카메라
   이름은 하나다.
6. **기본 전송을 `shm` 으로 올린다.** `direct` 는 폴백으로만 남는다.

## 4. 원칙

- **세그먼트가 있다 ⇔ 등록된 카메라가 연결돼 있다.** 미등록 장치는 세그먼트를 갖지 않는다.
- **데이터 플레인**(수집·추론·검출·스냅샷)은 스트림 이름으로 말한다.
  **관리 플레인**(카메라 페이지·프로파일·컨트롤·리셋)은 장치 id 를 그대로 쓴다.
- 소비자는 이름 규칙을 직접 계산하지 않는다 — **스트림 디렉토리에 조회한다.**

## 5. 설계

### 5-1. 이름

- 이름은 **등록할 때** 정해진다. 기본값 = `슬러그(장치 이름)_N`, N 은 그 기반에서 안 쓰인
  가장 작은 번호. 한 장뿐이어도 `_1` 이 붙는다. 슬러그가 비면(장치 이름이 비영문) `cam`.
- **허용 문자는 영문자·숫자·`_`·`-`, 첫 글자는 영숫자, 길이 1~40.** 이름이 세그먼트 파일
  이름(`/dev/shm/piper.cam.<이름>`)이자 CLI 인자·URL·JSON 값이라 그 밖의 문자(공백·`/`·`.`·`=`·
  한글)는 입력에서 거절한다. 기본 이름을 만들 때만 비허용 문자열을 `_` 하나로 줄인다.
  비교는 대소문자를 무시한다(혼동 방지).
- **유일해야 한다.** 등록·개명 때 검사하고 충돌이면 거부한다.
- **별칭(`label`)을 흡수한다.** `CameraInfo.label` · `POST /api/cameras/label` · 등록 요청의
  `label` 이 전부 이 이름 하나가 된다. 표시명(`display_name`)은 등록된 카메라면 스트림
  이름, 아니면 장치 이름이다.
  - `/label` 과 등록의 `label` 은 한 릴리스 동안 **개명의 별칭**으로 남긴다 — 낡은 번들을 든
    브라우저가 호출해도 죽지 않는다(이 저장소에서 실제로 겪었다). 비허용 문자면 400 과 사유.
  - **기존 별칭 마이그레이션.** 허용 문자로 쓸 수 있는 별칭(`Top_View`, 공백은 `_`)은 그
    카메라의 이름이 된다. 못 쓰는 별칭(`탑뷰`)은 기본 이름을 받고, 그 사실을 **안내로
    남긴다** — 조용히 사라지면 사람이 정한 값이 흔적 없이 없어진다. 시작할 때 일어나는 일이라
    그 순간엔 브라우저가 없다 — 파일(`camera_notices.json`)에 남기고, 카메라 페이지가 배너로
    보여 주고 사람이 지운다.
- 저장: 카메라 세션(`camera_session.json`)에 `stream` 으로 둔다(`label` 은 더 쓰지 않는다).
  이미 등록된 카메라는 첫 로드 때 위 규칙으로 이름을 받는다.
- **개명 이력(alias)**: 옛 이름은 같은 카메라로 해석한다. 저장된 매핑(브라우저 localStorage)이
  개명으로 깨지지 않게 한다. 규칙 두 개 — **현재 이름이 alias 보다 우선**하고, 기본 번호
  매기기는 alias 가 쥔 이름을 건너뛴다(옛 이름이 다른 카메라로 재사용되는 걸 막는다).
- **개명은 수집·추론이 도는 동안 막는다.** 연결된 카메라의 세그먼트가 옮겨지면 읽던 쪽이
  얼어붙으므로 409 와 사유를 돌려준다. 도는 게 없으면 데몬이 세그먼트를 새 이름으로 다시 만든다.
  ("이 카메라를 읽는 곳이 있는가"로 좁히지 않았다 — 카메라 페이지의 미리보기도 소비자라, 개명
  입력이 있는 바로 그 화면에서 늘 막히게 된다.)
- LeRobot 카메라 키(`top`)는 **전혀 다른 값**이다. 스트림 이름을 바꿔도 데이터셋 피처와
  학습된 정책은 영향이 없다 — 매핑만 `{top: 새이름}` 이 된다.

### 5-2. 수명 주기

```
스캔(미등록)  ── 데몬이 직접 열어 JPEG 1장 → RPC 결과로 반환 → 닫음.  세그먼트 없음
등록          ── 이름 부여 + connect  →  세그먼트 생성
연결 중       ── 세그먼트 발행. 웹 프리뷰·수집·추론이 전부 여기서 읽는다
연결 해제 / 유휴 종료 / 뽑힘  ── 세그먼트 제거. 등록은 남는다 (선택기에서 비활성)
```

- 스캔 썸네일은 **게이트웨이 메모리에 캐시**하고 미등록 카메라의 `/preview` 가 그걸 돌려준다.
  `probe` 가 세그먼트를 남기던 특수 경로(`unlink_segment=False`)가 사라진다 — 정지 화면
  세그먼트라는 함정이 구조로 없어진다.
- 썸네일은 RPC 응답에 실린다(640×480 JPEG 수십 KB). 크기가 문제되면 스캔 전용 임시 파일로.

### 5-3. 선택기 규칙

| 상태 | 표시 | 선택 |
|---|---|---|
| 등록 · 연결됨 | 이름(mono) + 크기·fps + 장치명 보조 | 가능 |
| 등록 · 연결 안 됨 | 같은 줄, 회색 + 사유 (`연결 안 됨` / `USB 빠짐` / `유휴로 종료됨`) | **비활성** |
| 미등록 | 안 보인다 (카메라 페이지에서 등록) | — |

- **비활성 줄에 `연결` 버튼을 둔다(권고).** 비활성만 있으면 카메라 페이지를 갔다 와야 한다.
  유휴 종료를 켜면 이 경로가 흔해진다.
- `prepare_cameras` 는 **연결 안 된 카메라를 더 이상 열지 않는다** — "연결 안 됨" 으로
  거절한다. 연결된 카메라의 해상도·fps 재협상은 그대로 한다(수집 시작 요청이 프로파일을
  데몬까지 넘긴다).

### 5-4. 발행자가 이름을 받는다

지금은 발행자와 소비자가 같은 규칙 함수로 서로를 찾는다. 이름이 자유로워지면 규칙이 없으므로
**게이트웨이가 이름을 정하고 connect RPC 에 실어 보낸다.**

- `connect(cam_id, …, stream=이름)` → 데몬이 그 이름으로 발행. 데몬은 여전히 "이번 실행의
  LeRobot 키"를 모른다 — 카메라당 이름 하나만 안다.
- ⚠ **접두사로 소유를 가르던 정리가 깨진다.** camerad 는 `dev_*`, rsd 는 `rs_*` 만 치웠다
  ([camerad.py](../daemons/camerad.py), [rsd.py](../daemons/rsd.py)). 헤더 여유 칸(52→64B)에
  **발행자 pid** 를 넣고, 시작 시 "pid 가 죽은 세그먼트"를 치운다. 헤더 앞부분 포맷은 그대로라
  기존 리더는 읽는다(버전 불변).
- `connect` 외에 **세그먼트 개명 RPC**(발행 중인 카메라) 하나가 는다.

### 5-5. 유휴 자동 종료

**읽는 쪽은 수동적이다.** 지금 리더는 `PROT_READ` 로 매핑만 할 뿐 자기 존재를 알리지 않아
"읽는 곳이 없다"를 알 방법이 없다. 알리는 방식은 셋이다.

| 방식 | 크래시 | 비고 |
|---|---|---|
| 리더가 헤더에 카운터 증감 | ✗ 죽으면 영영 남는다 | 리더가 헤더를 써야 해서 읽기 전용도 깨진다 |
| 리더가 하트비트 파일 갱신 | ○ 오래되면 무효 | 초당 syscall, 컨테이너는 PID 가 안 보여 pid 생존 검사 불가 |
| **리더가 세그먼트 파일에 `flock(LOCK_SH)`** | **◎ 커널이 죽은 프로세스의 락을 푼다** | 데몬이 `LOCK_EX\|LOCK_NB` 로 **떠본다** — 실패 = 읽는 곳이 있다 |

**권고: flock.** 데이터 경로의 락이 아니다 — 라이터는 이걸 기다리지 않는다(프레임 읽기·쓰기는
여전히 락 없는 seqlock). "누가 붙어 있나"를 데몬이 주기적으로 **떠보는** 표지일 뿐이다.
`ipc: host` 라 컨테이너와 호스트가 같은 tmpfs inode 를 보므로 컨테이너 소비자도 잡힌다
(실기 확인 항목).

- **기본은 "읽는 쪽 = 소비자"** 로 두고, 상시 도는 감시자가 **`observer=True` 로 빠진다.**
  반대로 하면 소비자가 표지를 빠뜨려 **수집 도중 스트림이 닫힌다.** 이 방향이면 빠뜨려도
  "안 닫힐" 뿐이다.
  - 감시자(빠짐): `device_watch._survey_cameras`, `light_watch.sample`, `has_frame`,
    `_is_fresh`, `_wait_for_frame`, `_shm_dims`. 전부 몇 초마다 열었다 닫는다.
  - 소비자(붙음): `PiperShmCamera`, detectord, 카메라 페이지 프리뷰 스트림, 정렬·캡처.
- **판정은 데몬이 한다.** 카메라별 `idle_stop_s`(0 = 끔, **기본 끔**)를 connect 때 받고, 소비자가
  없어진 지 그만큼 지나면 그 카메라를 닫는다. 게이트웨이가 죽어도 동작한다(크래시 격리).
- **시작 요청이 스트림을 붙잡는다.** `prepare_cameras` 끝 → subprocess 기동 → 정책 로드 →
  카메라 연결 사이에 수 초~수십 초가 있다. 그 사이 스트림이 닫히면 안 되므로 시작 요청이
  데몬에 `hold(300초)` 를 보낸다 — 게이트웨이가 락을 쥐는 대신 **시각을 데몬에 맡겨** 수명
  관리가 없다. 하한 30초를 두어 설정 실수도 막는다.
- 닫힌 뒤 사유는 `유휴로 종료됨` 으로 선택기에 보인다.

## 7. 작업 단계

**0. ☑ 기본 전송 `shm`** — [config.py](../backend/app/core/config.py) 기본값 변경. 배포·`.env` 는
이미 shm 이라 동작은 안 바뀐다.

**1. ☑ 레지스트리 (게이트웨이)** — [camera_streams.py](../backend/app/services/camera_streams.py)
(규칙·기본 이름·유일성·개명 이력·`resolve`·디렉토리 한 줄) · `CameraInfo.stream`/`aliases`
(`label` 은 읽기 전용 별칭 프로퍼티) · 등록·개명·해제 · 세션 저장·복원과 **별칭 마이그레이션 +
안내** · `POST /api/cameras/rename`(`/label`·등록의 `label` 은 개명으로 유지) ·

**6. ☑ 유휴 자동 종료** — 카메라별 옵션(**끔이 기본**, 1·5·10·30분·1시간, 하한 30초).
- **표지**: 소비자가 세그먼트 파일을 열 때 `flock(LOCK_SH)` 를 건다(`Subscriber` 기본). 데몬이
  `LOCK_EX|LOCK_NB` 로 떠본다(`piper_shm.has_readers`). 커널이 죽은 프로세스의 락을 풀어
  하트비트가 없다. **데이터 경로의 락이 아니다** — 프레임 읽기·쓰기는 그대로 락 없는 seqlock.
- **관찰자**: 상시 도는 감시·스냅샷·존재 확인 열두 곳은 `Subscriber(observer=True)` 로 표지를
  안 건다. 소비자는 셋뿐(LeRobot 플러그인·detectord·MJPEG 미리보기) — **테스트가 목록을 못 박는다.**
  기본이 소비자인 이유는 방향이다: 감시자가 표지를 걸면 "안 닫힐 뿐"이고, 소비자가 빠뜨리면
  수집 도중 닫힌다.
- **판단은 데몬이 한다**(`piper_cam.idle.IdleReaper`, 세 데몬의 루프). 게이트웨이가 죽어도 돈다.
  새 동사 `set_idle`·`hold` — 연결 인자를 늘리지 않아 옛 데몬과 호환된다.
- **유예**: 연결할 때마다 시간이 다시 시작된다 · 시작 요청이 `hold(300초)` 로 소비자가 붙을 때까지
  붙잡는다(프로세스 기동 → 정책 로드 → 카메라 연결 사이에는 읽는 곳이 없다) · 하한 30초.
  게이트웨이가 임대를 직접 쥐는 대신 데몬에 시각을 맡겼다 — 수명 관리가 필요 없다.
- **모르면 안 닫는다**: 락을 못 걸었거나 떠보다 예외면 "읽는 곳이 있다"로 본다.
- **RealSense 는 참조를 전부 놓는다**(`disconnect(cam_id, True)`) — `connect` 가 부를 때마다
  참조가 하나씩 늘어(재협상 등) 한 번의 해제로는 안 닫혔다.
- **사유**: 닫으면 데몬이 `cam_idle_key` 에 기록하고(연결하면 지움), 선택기가 "유휴로 종료됨"
  이라고 말한다. 게이트웨이는 데몬이 **스스로** 닫은 것을 모르므로 이 기록으로
  `connected` 를 내린다(`sync_idle_stops` — 안 내리면 선택기가 닫힌 카메라를 연결됨으로 보인다).
  장치 감시도 이걸 먼저 반영해 세그먼트 소실을 "영상이 끊겼습니다"로 읽지 않는다.
- ☑ **실기 확인 (2026-10-14, 개발 기계의 D435 `top`)**: 이름이 `/dev/shm/piper.cam.top` 이 되고
  헤더 pid 가 rsd 와 같다 · 개명이 발행 중인 세그먼트를 옮기고 미리보기가 이어진다 · 유휴 30초 설정 시
  32초 뒤 닫히고 "유휴로 종료됨" · 읽는 프로세스가 있으면 50초 넘게 안 닫히고, 죽이면 32초 뒤 닫힌다 ·
  **컨테이너(`ipc: host`) 안에서 건 락이 호스트 데몬에서 보이고** 읽는 동안 안 닫힌다 · 실제 LeRobot
  플러그인이 `top` 으로 열어 프레임을 읽고 표지를 잡았다 풀었다 · 옛 별칭(`right`/`top`/`left`)이
  안내 없이 이름이 됐다. ☐ **안 해본 것**: D405 두 대(rsd 의 color-only 특수 경로 — hang 전례가 있어
  피했다) · 팔을 붙인 실제 수집·추론 한 바퀴.

**7. ☑ 카메라 페이지 상시 보기** (2026-10-15) — 등록한 카메라는 페이지에 들어오면 **바로 shm 에서 읽어**
보여 준다. `실시간 보기`·`업데이트` 버튼이 없다(등록이 곧 연결·발행이므로 켤 것도, 한 장 다시 찍을
것도 없다).
- **연결 하나로 전부 받는다** — `GET /api/cameras/live?ids=…`
  ([mjpeg.multiplex](../backend/app/services/mjpeg.py)), 조각마다 `X-Camera` 헤더. 카드마다 `/stream`
  을 걸지 않는 이유는 **브라우저 연결(오리진당 6, HTTP/1.1)** 이다: 카메라 6대(RealSense 는 color·depth
  각각)를 전부 띄우면 E-stop 버튼의 요청이 큐에 서서 나가지 못한다. `<img>` 는 이 형식을 못 풀어
  프론트가 `fetch` 로 읽어 조각을 가른다([useCameraLive.ts](../frontend/src/hooks/useCameraLive.ts)) —
  프레임은 React 상태를 거치지 않고 `<img>` 의 `src` 에 직접 건다
  ([LiveCameraFrame](../frontend/src/components/LiveCameraFrame.tsx), 주기 10fps).
- **탭이 가려지면 연결을 닫는다.** 안 보는 화면이 연결·인코딩을 쥘 이유가 없고, 읽는 곳이 없으면
  유휴 종료 옵션이 켜진 카메라는 닫힌다 — 돌아오면 아래가 다시 연다.
- **멈춘 카메라는 바로 다시 연다**(`useReviveStopped`) — 유휴 종료·프레임 시간 초과(`_declare_lost`)·
  데몬 재시작. 판정은 `ready && present !== false && (!connected || streaming === false)`.
  들어오는 즉시 한 번, 이후 목록이 갱신될 때마다 본다. **순서대로** 연다(RealSense 동시 초기화 방지).
  못 연 카메라를 쉬지 않고 두드리지 않는다 — 시도 사이 0·10·30초, **세 번에서 멈춘다**(멈춘 장치를
  반복해서 여는 것이 D405 D-state 의 대표 경로). 이후는 카드의 `다시 연결` 이다. 뽑힌 카메라
  (`present === false`)는 건드리지 않는다.
- **자동 연결이 쉬는 때**: 하드웨어 리셋 중, **설정 모달이 열려 있는 동안.** 연결은 프로파일 컨트롤을
  다시 걸어서, 사람이 만지는 중인 장치 값(회색 카드 보정 직후)을 덮어쓴다 —
  [gray-card-calibration.md](gray-card-calibration.md) §4. 모달을 닫은 뒤 멈춰 있으면 그때 연다.
- **`해제`(등록 해제)만 남았다.** 카드에서 연결만 끊는 버튼은 없다 — 안 쓰는 카메라를 닫고 싶으면
  유휴 종료 옵션이다. `POST /api/cameras/probe`·`/disconnect` 는 API 로 남아 있다.

## 8. 건드리지 않는 것

- LeRobot 카메라 키와 정책·데이터셋 스키마.
- shm 플러그인([pipershmcamera.py](../vendor/lerobot_camera_pipershm/lerobot_camera_pipershm/pipershmcamera.py))
  은 이미 `segment` 를 받는다. **wrapper 도 그대로다.**
- 프레임 읽기·쓰기는 락 없는 seqlock 그대로다. 유휴 표지는 그 경로 밖에 있다.
- `test_segment_name_comes_from_the_device_not_the_lerobot_key`
  ([test_shm_transport.py](../backend/tests/test_shm_transport.py)) 는 **다시 쓴다** — 그 테스트가
  못 박던 "이름은 장치 id 규칙에서 나온다" 가 이 기획에서 바뀌는 지점이다. 지키려던 것
  (발행자가 실행별 LeRobot 키를 모른다)은 그대로 지킨다.

## 9. 위험

- **한 스트림 이름 = 한 발행자.** 세그먼트는 단일 라이터 seqlock 이다
  ([frames.py](../shm/piper_shm/frames.py)). 이름 유일성 검사가 곧 이 계약이다.
- **개명 중 소비자.** 막는다(§5-1). 막지 못한 소비자는 `orphaned` 로 얼어붙은 화면을 본다.
- **저장값 오염.** 정규화 실패 시 시작을 거부한다. 다른 카메라에 붙이지 않는다.
- **유휴 종료가 수집 도중 닫는 사고.** 소비자 기본·감시자 예외 방향(§5-5)과 시작 임대·하한 30초가
  막는다. 구현 때 "소비자가 표지를 빠뜨리면" 시나리오를 테스트로 못 박는다.
- **`direct` 폴백.** 이름 레지스트리는 전송과 무관해 `direct` 에서도 이름을 쓴다 — 시작할
  때 이름 → 장치 id 역변환으로 옛 설정을 만든다. 유휴 종료는 shm 전용이다(세그먼트가 없다).
- **영문 한정이 기존 별칭을 지운다.** 한글 별칭은 마이그레이션 때 기본 이름으로 바뀐다.
  일회성 안내가 이를 말하지만, 안내를 놓친 사람은 어느 카메라가 "탑뷰"였는지 장치 이름으로
  다시 찾아야 한다 — 카메라 페이지의 미리보기가 그 단서다.
- **데몬과 게이트웨이의 버전 어긋남.** `connect` 시그니처가 바뀐다. 옛 데몬은 `stream` 을
  모르므로 배포 때 데몬 재시작이 필요하다([service-restart.md](service-restart.md)의 낡은 코드 감지가
  이미 이걸 본다).

## 10. 열린 질문

없다. 직전까지 열려 있던 둘 — 별칭 통합(**합친다, 영문만**)과 기본 전송(**shm 으로 올린다**) —
은 §3 의 5·6 으로 확정했다.

  무시) · 옛 별칭 마이그레이션(쓸 수 있는 것은 이름이 되고 못 쓰는 것은 기본 이름 + 안내) ·
  `/label`·등록 `label` 이 개명으로 동작 · alias 우선순위 · 옛 id/옛 이름/새 이름이 같은
  설정을 만든다 · 연결 안 된 스트림 거절 · 미등록은 세그먼트를 만들지 않는다(probe) ·
  이름 모양 의존이 소비 경로에 없다(정적 테스트) · 소비자 없을 때만 유휴 종료 · 감시자는
  표지를 안 잡는다 · 소비자가 붙어 있으면 개명 409.
- **프론트**: `npm run build` (`tsc --noEmit` 은 no-op).
- **실기(.120)**: D405 + 웹캠 — 개명 후 수집 1 에피소드와 추론 1 회 · 컨테이너 소비자의 flock 이
  데몬에서 보이는지 · 유휴 종료 후 `연결` 로 복귀 · USB 재열거 뒤 매핑이 그대로 같은 카메라인지.
