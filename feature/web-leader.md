# 웹 리더 — 키보드·마우스로 팔을 조종한다

> 요청(2026-09-10): "simd 에서 리더암이 없는 유저는 어떻게 팔을 조종할까? 키보드·마우스
> 버튼·휠·이동으로 편리하게 매핑해 봐. 관절 모드든 엔드이펙터 모드든."

## 0. 요지

새 조종 경로를 만들지 않는다. 브라우저의 키·마우스 입력을 게이트웨이가 **가상 리더
세그먼트** `piper.arm.web_leader1.state` 로 발행하고, 나머지는 있는 그대로 쓴다 —
릴레이(리더 → 팔로워, 관절 모드)가 팔을 움직이고, 수집은 `web_leader_shm`
텔레오퍼레이터(so101 리더 플러그인의 동생)가 그 세그먼트를 읽는다. 실물 SO-101 리더·
스크립트 리더(sim-env.md §5)·웹 리더가 **같은 계약**이라 시뮬이든 실기든 팔로워는 모른다.

관절 모드는 관절 속도를, 엔드이펙터(EE) 모드는 말단 속도(6D)를 적분한다. EE 는
릴레이의 POSE 경로와 같은 IK(`ArmModel.ik` + 바닥 가드)로 관절 목표가 된다 — 단
**리더가 Piper 관절 그 자체**라 SO-101 때 팔이 꼬였던 크로스 모델 문제가 없다.

## 1. 지금 있는 것 (근거)

| 사실 | 뜻 |
|---|---|
| 릴레이: 리더 세그먼트 → 팔로워 action, **30Hz**, 데드맨 500ms, 리더가 0.5초 낡으면 전송 보류 | 웹 리더는 세그먼트만 채우면 된다. 브라우저가 멈추면 0.5초 안에 팔이 선다 |
| `filter_goal`: 관절당 한 걸음 상한(`step_limit`, 기본 20 norm/걸음) + 범위 + 바닥 | 키를 아무리 눌러도 팔로워가 튀지 않는다 — 속도 상한은 이미 robotd 에 있다 |
| POSE 경로: `ArmModel.fk/ik(target, seed)`, `lowest_z` 바닥 가드, 실패 시 `_block("도달 불가")` | EE 모드가 쓸 IK 와 거절 문구가 이미 있다 |
| `so101shmleader.py`: `StateReader(리더)` + 팔로워 앵커 → `get_action` | `web_leader_shm` 은 캘리브레이션·스팬이 없는 더 단순한 동생이다 |
| JogPanel: 슬라이더뿐, 키·마우스 입력 없음. 카메라는 `RecordPreview` 로 본다 | 조종 UI 는 카메라 위에 얹는 새 오버레이다 |
| sim-env.md §5 "리더는 셋 중 고른다" | 이 문서가 그 셋째(웹)를 실제 리더로 만든다 |

## 2. 구조

```
브라우저 (키·마우스, 30Hz 상태 전송)          게이트웨이                              팔로워
  ┌ 속도 적분기 ─┐  POST /api/leader/web/input  ┌ WebLeader ─┐  StateWriter   ┌ relay ─┐  action  ┌ robotd/simd ┐
  │ 관절 or EE   │ ───────────────────────────▶ │ 목표 자세   │ ─────────────▶ │ 30Hz   │ ───────▶ │ filter_goal │
  │ 눌림/이동    │      (WS 로 승격 가능)        │ (IK: EE)    │ web_leader1    │ 관절 복제│           │ deadman     │
  └──────────────┘                              └─────────────┘  .state         └─────────┘           └─────────────┘
                                                                        ▲
                                            수집: lerobot record  ── web_leader_shm.get_action() ──┘
```

- **가상 리더의 상태 = "리더가 지금 가리키는 자세"**(정규화 7f). 브라우저는 자세가
  아니라 **속도**(눌린 키·마우스 델타)를 보낸다. 적분은 게이트웨이가 한다 — 브라우저
  탭이 멈추거나 이벤트가 씹혀도 게이트웨이의 속도 벡터는 **입력이 100ms 이상 안 오면 0**
  이 된다. 팔은 그 자리에 선다. 데드맨 두 겹(입력 → 리더, 리더 → 팔로워).
- 시작 자세 = 팔로워의 지금 자세(SO-101 정합과 같은 앵커). 점프 0.
- EE 모드: 목표 6D 를 적분 → IK(시드 = 직전 해) → 관절 목표. 실패(도달 불가·특이점·
  바닥)면 **목표를 되돌리고** 화면에 이유. 릴레이 POSE 의 `_block` 그대로.
- 릴레이는 같은 모델(Piper → Piper)이라 **절대 복제**다 — 크로스 정합·클러치 없음.
  시뮬(`sim_follower1`)도 실기(`can0`)도 팔로워일 뿐이다.

## 3. 입력 매핑

원칙: **오른손 마우스가 메인**(이동·회전·그리퍼), 왼손은 수식어(`Shift` 회전, `Ctrl` 미세)와 모드 키. 관절 모드는 키보드가 편하다(손가락 하나가 관절 하나). 누르는 동안 움직이고 놓으면
선다. 속도: 관절 모드는 `Shift` 빠르게 ×3·`Ctrl` 미세 ×0.25, EE 모드는 마우스 속도가 곧 속도이고 `Ctrl` 미세만. 어느 모드든
`Space` = 그 자리에 정지(속도 0), `Esc` = 조종 끝(릴레이 정지·포인터 락 해제),
`Tab` = 관절/EE 모드 전환, `H` = 저장된 파킹 자세로(확인 모달), `?` = 키맵.

### 관절 모드 (6관절 + 그리퍼)

| 입력 | 동작 | 이유 |
|---|---|---|
| `Q`/`A` `W`/`S` `E`/`D` `R`/`F` `T`/`G` `Y`/`H` | 관절 1~6 을 +/− 로 (위 줄 +, 아래 줄 −) | 손가락 하나가 관절 하나. 손을 안 옮긴다 |
| `[` / `]` , 마우스 **휠+Ctrl** | 그리퍼 닫기/열기 | |
| `1`~`6`, `7` | "선택 관절" 지정 (화면에 하이라이트) | 휠·드래그의 대상 |
| 마우스 **휠** | 선택 관절을 한 틱에 한 걸음(기본 2 norm) | 정밀 조정 — 휠은 이산 입력이라 미세 조정에 맞다 |
| **우클릭 드래그** | 가로 → 관절 1(베이스 회전), 세로 → 관절 2(어깨) | 두 관절 동시, 손이 직관적으로 아는 방향 |
| **우클릭+Shift 드래그** | 가로 → 관절 4(전완 롤), 세로 → 관절 3(팔꿈치) | |
| **가운데 버튼 드래그** | 가로 → 관절 6(손목 롤), 세로 → 관절 5(손목 피치) | |

### 엔드이펙터 모드 — **마우스가 메인이다** (사용자 제안 2026-09-10)

축이 셋(x·y·휠)뿐인 마우스로 6D 를 다루는 법: **Shift 를 누르면 그 세 축이 전부
회전이 된다.** 이동과 회전이 한 손 안에서 갈리고, 왼손은 수식어만 잡는다.

| 입력 | 동작 | 이유 |
|---|---|---|
| **마우스 이동**(포인터 락) | 가로 → y, 세로 → x — 테이블 면에서 끈다 | 탑뷰에서 "물체 쪽으로 끈다" 가 곧 이동이다 |
| **휠** | z 올리기/내리기 (한 칸 5mm, Ctrl 1mm) | 휠은 위아래 |
| **Shift + 이동** | 가로 → 요(yaw), 세로 → 피치(pitch) | 자세 = 같은 손, 수식어 하나 |
| **Shift + 휠** | 롤(roll) (한 칸 3°) | 세 번째 회전축 |
| **왼쪽 버튼** | 누르는 동안 그리퍼 **닫힘**, 놓으면 멈춤 — 짧게 클릭(<150ms)은 끝까지 | 집는 순간 손을 안 옮긴다. 살살 쥐기도 된다 |
| **오른쪽 버튼** | 누르는 동안 그리퍼 **열림**, 짧게 클릭은 끝까지 | |
| **가운데 버튼** | 자세 고정 토글 — 켜면 이동만, 말단 방향 유지 | 집기 자세를 잡은 뒤 옮길 때 |
| `Ctrl` | 미세 ×0.25 (이동·회전·휠 모두) | 속도 단계는 마우스 속도 자체가 대신한다 — 빨리 움직이면 빨리 간다 |
| `W/S A/D Q/E`, `I/K J/L U/O`, `[ ]` | 키보드 대체 — x/y/z, 피치/요/롤, 그리퍼 | 트랙패드(포인터 락이 어색함)·한 손 조작용 |

- **첫 클릭은 포인터 락**이다 — 오버레이를 눌러야 락이 걸리고, 그 클릭은 그리퍼를
  건드리지 않는다. 락이 걸린 뒤부터 버튼이 그리퍼다. `Esc` 로 락이 풀리면 버튼도 그리퍼가
  아니다(브라우저 규칙).
- Shift 를 누르는 순간 이동 적분이 멈추고 회전 적분이 시작된다 — 드래그 중에 전환해도
  튀지 않는다(속도 적분이라 위치는 이어진다).
- 감도: 300px = 이동 6cm / 회전 30°, 설정 슬라이더로 조정(DPI 가 다르다).
- 관절 모드의 마우스(휠 = 선택 관절, 우드래그 = 두 관절)는 그대로다 — 모드가 다르면
  버튼 뜻이 달라지는 것을 HUD 가 보여 준다.

### 왜 마우스 이동은 "포인터 락"인가

일반 마우스 이동은 화면 가장자리에서 멈추고 커서가 딴 데를 누른다. Pointer Lock
API 로 잡으면 델타만 오고 커서가 사라진다 — 게임 조작감. `Esc` 로 풀린다(브라우저
규칙). 락은 조종 오버레이를 **클릭해야** 걸린다 — 실수로 걸리지 않는다.

## 4. 안전

- **입력 데드맨**: 게이트웨이는 마지막 입력 후 100ms 가 지나면 속도를 0 으로. 브라우저는
  30Hz 로 "지금 눌린 것"을 보낸다(키 반복이 아니라 상태). 탭이 숨겨지거나
  (`visibilitychange`) 창이 포커스를 잃으면(`blur`) 즉시 정지 상태를 보낸다.
- **릴레이 데드맨**(500ms)과 **robotd 데드맨**은 그대로 — 세 겹.
- `Space` 는 정지이지 E-stop 이 아니다. E-stop 은 기존 버튼/heartbeat 그대로. 오버레이
  안에서 `window.confirm` 을 쓰지 않는다(heartbeat 를 막는다 — 기존 규칙).
- 관절 범위·바닥·걸음 상한은 robotd 의 `filter_goal` 이 지킨다. EE 의 바닥 가드는
  IK 단계에서 한 번 더(릴레이 POSE 와 같다).
- 배타: 웹 리더 릴레이도 `teleop_session` 을 쥔다 — 조그·다른 릴레이·추론과 동시에 못 켠다.
  [해제] 의미(팔로워를 놓는다)는 v0.4.5 규칙 그대로.
- 실기 첫 사용: 속도 기본이 시뮬의 절반, 화면 위에 "실기" 붉은 띠.

## 5. 화면 — **별도 브라우저 창** (사용자 결정 2026-09-10)

**수집 페이지는 건드리지 않는다.** 시뮬이라고 모드가 생기지 않는다 — 수집 화면의 리더
선택에 "웹 리더(키보드·마우스)" 가 SO-101 옆에 하나 더 생길 뿐이다. 조종은 **새 브라우저
창**이 맡는다. div·모달이 아니라 `window.open` 으로 띄우는 진짜 창이다:

- **왜 창인가.** 키보드 입력은 포커스를 가진 문서 하나가 받는다. 메인 앱 안의 div 면
  슬라이더·입력칸·단축키와 키가 부딪히고, 스크롤·모달이 조종 도중 끼어든다. 창을
  따로 두면 그 창의 모든 키·버튼·휠·이동이 조종이고, 메인 창은 수집·설정을 그대로 한다.
  모니터가 둘이면 조종 창을 한쪽에 둔다.
- **라우트** `/teleop?follower=<iface>` — 앱 셸(내비·상단바) 없이 카메라 + HUD 만.
  열기는 사용자 클릭에서만(`window.open(url, "piper-teleop", "popup,width=1280,height=800")`)
  — 팝업 차단은 클릭에서 열면 안 걸린다. 이름을 고정해 두 번 눌러도 **같은 창**이
  앞으로 온다(창 둘이 한 팔을 조종하는 일이 없다).
- **여는 자리**: 로봇 페이지의 팔 카드 [조종 창 열기] (시뮬 팔에도 실기 팔에도 같은 버튼),
  수집 페이지에서 리더가 "웹 리더" 면 [조종 창] 링크 하나 — 페이지 자체는 그대로다.
- **로봇 페이지에 웹 리더 카드는 없다.** 장치가 아니다 — 포트도, 연결도, 캘리브레이션도
  없다. 등록부(`robot_manager.arms`)에 넣으면 스캔·lost·세션·좌우 짝 맞추기·마스터/
  슬레이브가 전부 "이건 뭐지" 하고 특례를 요구한다. 대신 **팔로워 카드**에 [조종 창 열기]
  가 있고, 조종 중엔 그 카드의 상태 줄이 "웹 리더 → sim_follower1 · 관절 모드" 라고
  말한다. 릴레이는 `leader="web_leader1"` 을 명시해 시작하므로 조그 패널의 "같은 쪽
  리더" 규칙(사람 손 방향과 팔 방향을 맞추려는 것)을 타지 않는다 — 키보드에는 좌우가 없다.
- **창 안**: 카메라(시뮬은 탑·정면·손목 셋 다, 실기는 등록된 것) — 하나 크게 + 나머지
  작게, 클릭으로 바꾼다. 위에 얇은 HUD:

```
┌ 조종 — sim_follower1 ──────────────────────────────────────────────┐
│ 모드: 관절 | EE     Ctrl 미세   Shift 회전(EE)     ● 조종 중 · Esc 끝   ? │
│                                                                    │
│   [ 탑뷰 (크게) ]                                    [정면] [손목]  │
│                                                                    │
│ J1 +12 J2 -40 J3 55 J4 0 J5 20 J6 0 G 35   x .32 y .01 z .12  ⚠ 바닥 한계 │
└────────────────────────────────────────────────────────────────────┘
```

- 창을 **클릭**하면 포인터 락 + 조종 시작(릴레이 start, 앵커 = 지금 자세). `Esc` 로 락이
  풀리면 조종은 멈추지만 릴레이는 살아 있다(다시 클릭). 창을 **닫으면**(`pagehide`)
  릴레이 정지 — 놓친 경우도 입력 데드맨(100ms)이 리더를 세운다.
- 창이 포커스를 잃으면(`blur`, 다른 창 클릭) 즉시 정지 상태를 보낸다. 눌린 키가
  남아 "계속 움직이는" 일이 없다.
- **heartbeat**: 이 창도 E-stop heartbeat 를 보낸다(메인 창과 같은 훅). 메인 창을
  닫아도 조종 창이 살아 있으면 팔은 선다 — 텔레옵은 E-stop 대상이다.
- HUD 는 브라우저 DOM 이다 — 수집 프레임은 카메라 데몬의 `/dev/shm` 원본을
  `lerobot_camera_pipershm` 이 직접 읽으므로 **오버레이는 데이터에 안 들어간다.**
  화면 캡처로 수집하는 길은 애초에 없다.
- IK 거절·필터 클램프(`blocked`)는 HUD 한 줄. 15Hz 로 뱉지 않는다(릴레이 규칙). `?` 는 키맵.
- 선택 관절·눌린 키·Shift 상태가 HUD 에 켜진다 — "지금 무엇을 움직이는가"가 보여야
  실수가 준다.

## 6. 수집·시뮬

- `web_leader_shm` 텔레오퍼레이터(`vendor/lerobot_robot_pipershm`): `StateReader("web_leader1")`
  → `get_action` 은 그 자세 그대로(Piper 관절 정규화 → LeRobot action). so101 것에서
  스팬·정합을 뺀 것. 수집 화면은 리더 선택에 "웹 리더(키보드·마우스)" 가 하나 더
  생길 뿐 **시뮬 모드 같은 것은 없다** — 조종은 별도 창(§5)이 한다.
- 데이터셋의 action 의미는 실물 리더와 같다("리더가 가리키는 자세"). ACT 학습 무수정.
- 시뮬 4단계(스크립트 시연)와 세그먼트가 같다 — 사람이 키보드로 시연한 에피소드와
  스크립트 시연을 섞어 학습할 수 있다.
- **시뮬에서 먼저**: 시뮬 팔로워로 매핑·속도를 튜닝하고 실기로 간다. 큐브 집기 1회
  성공까지 걸린 시간을 처음부터 잰다 — 매핑이 좋은지의 숫자.

## 7. 순서

1. ✅ **가상 리더 + 관절 모드(키보드) + 조종 창** (2026-09-10) — `app/services/web_leader.py`
   (속도 적분·입력 데드맨 100ms·`StateWriter("web_leader1")`·릴레이 start/stop),
   `POST /api/leader/web/start|input|stop`, `GET /status`, `/teleop` 창(standalone 페이지,
   카메라 스트림 + HUD, 포인터 락, blur/pagehide 정리, heartbeat), 로봇 카드 [조종 창 열기]
   (이름 고정 창). 실측(시뮬): Q 1초 → 리더·팔로워 joint1 32(30 norm/s + 지연), 입력 끊고
   0.5초 뒤 팔로워 그대로(멈춤), Shift+A 0.5초 → −45(×3), 클릭 close → 그리퍼 0, 끝내면
   릴레이·teleop 잠금·세그먼트가 사라지고 이후 입력은 409.
2. ✅ **마우스 + EE 모드** (2026-09-10, 백엔드·창) — 목표 6D 적분 → `ArmModel.ik`(시드 =
   직전 해) → 관절, 튐(25°)·바닥·잔차로 거절하면 목표 되돌림. 실측(시뮬, 작업 자세에서):
   마우스 앞 1초 → x +8.7cm(팔로워 j2 −37→−16, j3 64→49), 휠 0.6초 → z −9cm, Shift+가로 →
   요 −18°, Shift+휠 → 롤 −35°, 거절 0. 잡은 것 둘: ① IK 의 `ok` 는 한계 근처에서 2mm
   잔차로도 False 라 조종이 아예 안 됐다 → 잔차 5mm/3° 안이면 해로 받는다(다음 틱이 이어
   간다); ② `rpy_from_matrix` 는 이미 도(°)라 두 번 바꿔 4873° 가 찍혔다. ⚠ **창 자체는
   사람 손으로 아직 안 눌러 봤다** — 소스 대조 테스트와 빌드까지. 감도·속도 튜닝은 그때.
3. ✅ **수집** (2026-09-10) — **새 플러그인이 필요 없었다.** 웹 리더 세그먼트는 Piper
   관절 그 자체라 기존 `piper_leader_shm`(읽기 전용 `StateReader(port)`)이 `teleop_port=
   web_leader1` 로 그대로 읽는다. 대신 배타를 풀어야 했다: 수집 중엔 녹화 프로세스가
   팔로워 명령 세그먼트를 쥐므로 릴레이가 같이 쥘 수 없다 → 수집 시작이 `require_idle`
   **앞에서** 릴레이를 놓고(`web_leader.release_follower`), 웹 리더는 발행만 한다
   (`start(relay=False)`); 창은 "수집 중 — 녹화가 팔을 움직임, 여기선 입력만" 을 띄운다.
   수집 화면은 리더 선택에 "웹 리더(키보드·마우스)" 옵션과 [조종 창 열기] 하나뿐이다.
   실측(시뮬 E2E): 릴레이로 조종 중 → 수집 시작 → `relaying False / publishing True`,
   activity = recording → 에피소드 중 Q 2초에 팔로워 joint1 −13→50(녹화 프로세스가
   움직임) → 2 에피소드 147 프레임, action 열 = 웹 리더 자세(−13..50), 관측 = 팔로워
   (−13..51), 영상 키 top·left_hand. 잡은 것: 라우터 안의 지역 `import asyncio` 가 함수
   전체에서 asyncio 를 지역 변수로 만들어 앞쪽 사용이 UnboundLocalError — 지역 import 제거.
4. **실기** — 속도 절반(`speed_scale=0.5`, 구현됨)·창의 붉은 "실기" 띠(구현됨). can 팔로워로
   같은 절차를 **사람이** 돌려 보고 튜닝값을 적는다 — 아직 안 했다.

## 8. 위험

| 위험 | 대응 |
|---|---|
| 키 반복 지연·씹힘(OS 키 반복 설정) | 키 반복을 안 쓴다 — keydown/keyup 으로 "눌린 집합"을 30Hz 로 보낸다 |
| 브라우저가 멈췄는데 마지막 속도로 계속 움직인다 | 게이트웨이 입력 데드맨 100ms. 브라우저가 아니라 **게이트웨이가** 적분한다 |
| EE 모드에서 IK 가 특이점 근처에서 튄다 | 시드 = 직전 해, 관절 걸음 상한(`POSE_MAX_JOINT_STEP_DEG`)으로 거절, 목표 되돌림 |
| 마우스 델타가 DPI 마다 다르다 | 감도 슬라이더(기본 300px 기준), 설정에 저장 |
| 지연(브라우저 30Hz → 리더 → 릴레이 30Hz): ~70~100ms | 시뮬에서 잰다. 부족하면 입력 채널을 WS 로 승격 |
| 실기에서 실수 | 속도 절반, 바닥·범위·걸음 상한은 이미 robotd, 첫 사용은 시뮬 |

## 열린 질문

- 게임패드(Gamepad API)는 같은 적분기에 축만 더하면 된다 — 요청이 있을 때.
- 사용자 재매핑(키 바꾸기) — v2. 처음엔 고정 키맵 + 감도만.
- 카메라 기준 좌표계(EE 이동을 "화면 기준"으로) — 탑뷰에선 베이스 기준과 같고, 손목뷰에선
  다르다. 처음엔 베이스 기준, 손목뷰 기준은 써 보고 정한다.
