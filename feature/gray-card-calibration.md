# 회색 카드 보정 — 색·밝기를 재현 가능하게

## 1. 왜

정책은 색에 민감하다. 오전에 모은 데이터와 오후에 도는 추론이 **화이트밸런스만
달라도 다른 관측**이 된다. 카메라가 둘이면 서로도 안 맞는다 — 탑뷰와 손목이 같은
물체를 다른 색으로 보면 정책은 그걸 **다른 물체의 특징으로 배운다.**

지금은 사람이 노출·WB 슬라이더를 감으로 맞춘다. 다음 주에 같은 값이 나올 이유가 없다.
회색 카드는 **재현 가능한 기준점**을 준다: "이 카드가 중성 회색으로, 정해진 밝기로."

> ⚠ **기하 보정이 아니다.** 렌즈 왜곡·초점거리·카메라 간 위치는 체커보드가 필요하고
> 여기서 다루지 않는다. 회색 카드로 할 수 있는 것은 **광학(색·밝기)** 뿐이다.

## 2. 절차 — 노출은 자동에게, WB 는 우리가 잰다 (2026-09-02 개정)

```
1. 자동 노출만 켜고 기다린다 (AWB 는 안 켠다 — 아래)
2. 자동을 끈다              ← AE 가 찾은 노출이 얼어붙는다
3. WB 를 카드로 직접 맞춘다  ← 카드의 R/B 균형까지 비례 보정 (최대 3회)
4. 카드를 재서 밝기(노출 또는 gain)를 비례 보정한다 (최대 3회)
5. 다시 재서 결과를 보고한다
```

**⚠ AWB 는 못 쓴다 — 처음 설계가 틀렸었다.** 원래는 "자동 WB 를 켜서 맞추고
꺼서 얼린다"였는데, 실측(2026-09-02)으로 그 전제가 깨졌다: **AWB 의 수렴값은
컨트롤 읽기에 반영되지 않고, 끄면 마지막 수동 설정값으로 돌아온다.** 스트림을
켠 채 AWB 를 5초 수렴시켜도 읽기는 4600 그대로였다. 그 결과 모든 프로파일의
WB 가 공장값 4600 으로 저장돼 있었고, 조명이 4600K 에서 멀어질수록(저녁 형광등
비중 증가) 화면이 푸르게 치우쳤다 — 사용자가 실제로 겪은 그 증상이다.
그래서 WB 는 `white_balance_for`(graycard.py) 가 카드의 R/B 균형을 직접 재서
맞춘다. 카드가 푸르면 K 를 올린다 — 노출 보정과 같은 read-back 반복이다.

**노출은 여전히 자동에게 맡긴다.** AE 의 동결은 실측으로 성립한다 — 프로파일들의
노출값이 제각각인 것이 증거다.

**⚠ 끄는 것이 핵심인 건 그대로다.** 켜둔 채로는 카드를 치우는 순간 다시 흔들려
아무것도 재현되지 않는다.

**노출만 따로 보정하는 이유.** 자동 노출은 자기 측광 목표를 따르지 18% 회색을
목표하지 않는다. 밝기는 노출에 거의 비례하므로 한 번의 비례 보정으로 대부분 잡힌다.

**손잡이 선택 — 노출 고정 모드 (2026-09-02 추가).** 노출은 밝기만 정하는 게
아니라 **모션 블러와 프레임 예산**(긴 노출 = fps 상한)을 정한다. 로봇 데이터에서는
노출을 먼저 정해 두고 밝기는 gain 으로 잡고 싶을 때가 있어, `adjust="gain"` 이면
3단계가 gain 을 비례 보정한다(밝기는 gain 에도 거의 비례하고, read-back 반복이
남는 오차를 잡는다). 이 모드에서는 1단계에서 **자동 노출을 아예 켜지 않는다** —
켜는 순간 지금 노출이 움직여 "고정"이 거짓말이 된다. AWB 만 카드에 맞춘다.
화면에는 "노출 고정 — 밝기는 gain 으로만 보정" 체크박스로 나온다.

## 3. 못 믿을 측정은 거절한다

⚠ 포화되거나 얼룩진 카드로 정한 노출은 **다음 주에 재현되지 않는다** — 그게 이
기능의 존재 이유인데 스스로 깨는 셈이다. 그래서 재기 전에 막는다:

| 조건 | 뜻 |
|---|---|
| 포화 5% 초과 | 진짜 밝기를 모른다 — 노출을 낮추거나 조명을 줄여야 |
| 얼룩 12% 초과 | 그림자·반사가 걸렸다 |
| 영역 100픽셀 미만 | 카드가 너무 작다 |

실측으로 확인: 카드 없이 일반 장면에 대고 돌리면 **얼룩 12.3% 로 거절**된다.

**어두운 프레임의 폭주도 막는다.** 렌즈가 막혔거나 조명이 꺼진 상태에서 비례 보정을
그대로 믿으면 노출을 최대까지 밀어붙이고, 치우는 순간 다음 프레임이 새하얗게 된다.
배수를 0.25~4배로 제한한다.

## 4. 저장은 안 한다 — 프로파일이 한다

보정은 값을 **장치에 올려놓고 보고**만 한다. 저장은
[카메라 프로파일](camera-profiles.md)이 이미 하는 일이고, 그쪽은 **연결할 때 적용까지**
한다. 여기서 따로 저장하면 같은 값이 두 곳에 살게 된다.

즉 흐름은 `보정 → 결과 확인 → 마음에 들면 프로파일로 저장` 이다.

## 5. 실기 확인

D405 컬러, 카드 없이 일반 장면 (4.0초 소요):

```
밝기   151.7 → 125.4  (목표 118)
치우침   0.67% → 0.64%
노출          → 9.7ms
판정: 거절 — 카드 밝기가 고르지 않습니다(12.3%)
```

기계는 완주하고, **결과는 정직하게 거절**한다. 밝기는 허용 오차 안(±8)에 들어왔지만
대상이 카드가 아니므로 성공이라 하지 않는다.

## 6. 영역은 사용자가 고른다

**`보정 시작` 을 누른 뒤에만** 프리뷰에 노란 상자가 뜬다. 상자를 **클릭·드래그로
옮기고 휠로 키운 뒤** `이 영역으로 맞추기` 를 누른다. 기본 위치는 가운데 30%
상자(비네팅이 가장 적은 자리)지만, 카드를 가운데 두기 어려운 배치가 흔하다.

> 평소에 상자를 안 그리는 이유: 프리뷰는 대부분의 시간 **카메라가 제대로 보이는지
> 확인하는 화면**이다. 늘 떠 있는 조준 상자는 그때 방해만 되고, 지금 보정 중인지
> 아닌지도 흐려진다. 보정이 끝나면 상자를 치우고 결과를 보여준다.

**옮길 때마다 재서 숫자를 보여준다** (`measure-gray-card` — 장치를 안 건드리는
읽기 전용이라 배타 가드도 안 탄다). 그림자나 반사는 **눈으로 잘 안 보이고 얼룩 %
로만 드러난다** — 보정을 눌러보고 거절당하는 것보다 옮기면서 보는 편이 낫다.

실측(D405, 카드 없는 일반 장면)에서 자리마다 이만큼 갈린다:

```
roi=[  0,   0,120,120]  밝기  78.5  치우침 13.80%  얼룩 46.4%  거절
roi=[364, 180,120,120]  밝기  85.6  치우침  1.15%  얼룩  7.7%  OK
roi=[700, 340,120,120]  밝기 120.3  치우침  2.39%  얼룩 27.6%  거절
```

### 좌표는 프레임 기준이다

화면 크기가 아니라 **원본 프레임 픽셀**로 주고받는다 — 백엔드가 자르는 것은
프레임이고 화면 크기는 창을 줄이면 바뀐다.

> ⚠ **`object-contain` 이 레터박스를 만든다.** 848x480 을 `aspect-[4/3]` 상자에
> 넣으면 위아래에 빈 띠가 생기는데, 요소 좌표를 그대로 비율로 쓰면 그 띠만큼
> 어긋나 **상자가 손끝에서 미끄러진다.** `naturalWidth/Height` 로 실제 그려진
> 사각형을 먼저 구한다.

> ⚠ **휠은 네이티브 리스너로, 마우스를 받는 층에 단다.** 두 가지가 겹쳐 있다:
> React 의 `onWheel` 은 루트에 passive 로 붙어 `preventDefault()` 가 안 먹고(그러면
> 상자를 키우는 동안 설정 모달이 같이 스크롤된다), **이미지에 달면 아예 안 먹는다** —
> 상호작용 층이 이미지를 덮고 있고 둘은 형제라 wheel 이 이미지까지 안 간다.

> ⚠ **프리뷰는 200ms 마다 다시 로딩된다.** 설정 모달이 `src` 를 계속 갈아끼워
> 화면을 갱신하는데, 그 순간 `naturalWidth` 가 0 이 된다. 렌더할 때마다 이미지에서
> 크기를 읽으면 **상자가 5분의 1초마다 사라진다.** 크기를 state 에 담고 0 은
> 버린다 — 마지막으로 제대로 읽은 값을 계속 쓴다.

> ⚠ **휠 리스너는 콜백 ref 로 단다.** 상자는 첫 프레임을 읽기 전까지 렌더되지
> 않으므로, 마운트 때 한 번 도는 이펙트는 **붙일 요소를 못 찾고 끝난다** — 그러면
> 휠이 아예 안 먹는다. 값이 바뀔 때 다시 붙게 하면 이번엔 아래의 "크기 초기화"로
> 돌아간다. 콜백 ref 는 요소가 **생기는 순간** 불려 둘 다 피한다.

> ⚠ **휠 리스너를 값에 의존시키지 않는다.** `roi` 를 의존성에 넣으면 굴리는 내내
> 리스너가 떼였다 붙고, 그 틈에 들어온 이벤트가 **같은 옛 값에서 다시 계산**해
> 크기가 초기화된 것처럼 보인다. 최신 값은 ref 로 읽는다. 같은 이유로 측정은
> **멈춘 뒤에** 한 번만 보낸다(200ms 디바운스) — 틱마다 보내면 요청이 밀려
> 숫자가 뒤섞여 들어온다.

> ⚠ **바깥을 어둡게 할 때 거대한 그림자를 쓰지 않는다.** `shadow-[0_0_0_9999px_…]`
> 는 확산이 프리뷰를 넘어 **페이지 전체를 덮는다.** 상자 둘레를 네 조각으로 덮으면
> 컨테이너 밖으로 샐 수가 없다.

## 7. 아직 안 한 것

- **두 카메라 교차 확인** — 같은 카드로 둘을 보정한 뒤 "서로 얼마나 맞는가"를
  숫자로 보여주는 것. 정책에는 이게 실제 목표에 가깝다
- **camerad(USB 웹캠) 경로** — 순수 로직은 `piper_cam` 에 있어 공유 가능하지만
  절차는 rsd 에만 붙였다
