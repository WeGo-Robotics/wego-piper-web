# 회색 카드 보정 — 색·밝기를 재현 가능하게

## 1. 왜

정책은 색에 민감하다. 오전에 모은 데이터와 오후에 도는 추론이 **화이트밸런스만
달라도 다른 관측**이 된다. 카메라가 둘이면 서로도 안 맞는다 — 탑뷰와 손목이 같은
물체를 다른 색으로 보면 정책은 그걸 **다른 물체의 특징으로 배운다.**

지금은 사람이 노출·WB 슬라이더를 감으로 맞춘다. 다음 주에 같은 값이 나올 이유가 없다.
회색 카드는 **재현 가능한 기준점**을 준다: "이 카드가 중성 회색으로, 정해진 밝기로."

> ⚠ **기하 보정이 아니다.** 렌즈 왜곡·초점거리·카메라 간 위치는 체커보드가 필요하고
> 여기서 다루지 않는다. 회색 카드로 할 수 있는 것은 **광학(색·밝기)** 뿐이다.

## 2. 절차 — 자동에게 시키고 잠근다

```
1. 자동 WB·노출을 켜고 2초 기다린다
2. 자동을 끈다            ← 이게 "보정"의 실체다
3. 카드를 재서 노출만 비례 보정한다 (최대 3회)
4. 다시 재서 결과를 보고한다
```

**왜 켈빈 값을 탐색하지 않고 자동에게 맡기나.** 회색 카드는 자동 WB 가 가장 잘 맞는
조건이다 — 중성 피사체가 화면을 채운 상태가 그 알고리즘이 가정하는 바로 그 상황이다.
`white_balance` 는 켈빈 한 축(2800~6500)이라 이분 탐색을 짤 수도 있지만, 카메라 자기
알고리즘보다 나을 이유가 없고 왕복만 늘어난다.

**⚠ 끄는 것이 핵심이다.** 켜둔 채로는 카드를 치우는 순간 다시 흔들려 아무것도
재현되지 않는다. 자동은 *맞추는 방법*이고, 보정의 결과물은 *잠긴 값*이다.

**노출만 따로 보정하는 이유.** 자동 노출은 자기 측광 목표를 따르지 18% 회색을
목표하지 않는다. 밝기는 노출에 거의 비례하므로 한 번의 비례 보정으로 대부분 잡힌다.

## 3. 못 믿을 측정은 거절한다

⚠ 포화되거나 얼룩진 카드로 정한 노출은 **다음 주에 재현되지 않는다** — 그게 이
기능의 존재 이유인데 스스로 깨는 셈이다. 그래서 재기 전에 막는다:

| 조건 | 뜻 |
|---|---|
| 포화 5% 초과 | 진짜 밝기를 모른다 — 노출을 낮추거나 조명을 줄여야 |
| 얼룩 12% 초과 | 그림자·반사가 걸렸다 |
| 영역 100픽셀 미만 | 카드가 너무 작다 |

실측으로 확인: 카드 없이 일반 장면에 대고 돌리면 **얼룩 12.3% 로 거절**된다.

**어두운 프레임의 폭주도 막는다.** 렌즈가 막혔거나 조명이 꺼진 상태에서 비례 보정을
그대로 믿으면 노출을 최대까지 밀어붙이고, 치우는 순간 다음 프레임이 새하얗게 된다.
배수를 0.25~4배로 제한한다.

## 4. 저장은 안 한다 — 프로파일이 한다

보정은 값을 **장치에 올려놓고 보고**만 한다. 저장은
[카메라 프로파일](camera-profiles.md)이 이미 하는 일이고, 그쪽은 **연결할 때 적용까지**
한다. 여기서 따로 저장하면 같은 값이 두 곳에 살게 된다.

즉 흐름은 `보정 → 결과 확인 → 마음에 들면 프로파일로 저장` 이다.

## 5. 실기 확인

D405 컬러, 카드 없이 일반 장면 (4.0초 소요):

```
밝기   151.7 → 125.4  (목표 118)
치우침   0.67% → 0.64%
노출          → 9.7ms
판정: 거절 — 카드 밝기가 고르지 않습니다(12.3%)
```

기계는 완주하고, **결과는 정직하게 거절**한다. 밝기는 허용 오차 안(±8)에 들어왔지만
대상이 카드가 아니므로 성공이라 하지 않는다.

## 6. 아직 안 한 것

- **ROI 를 그려서 지정** — 지금은 화면 가운데 30% 상자 고정. 가운데가 비네팅이
  가장 적어 기본으로 맞지만, 카드를 가운데 두기 어려운 배치가 있으면 필요해진다
- **두 카메라 교차 확인** — 같은 카드로 둘을 보정한 뒤 "서로 얼마나 맞는가"를
  숫자로 보여주는 것. 정책에는 이게 실제 목표에 가깝다
- **camerad(USB 웹캠) 경로** — 순수 로직은 `piper_cam` 에 있어 공유 가능하지만
  절차는 rsd 에만 붙였다
