# 시뮬 데이터의 **출처 기록** 메우기 (기획)

> "가상환경에서 모은 데이터셋에 환경 구성이 다 들어가나, 가중치까지 가나, 남이 받아서
> 돌려도 되나" (사용자 질문 2026-09-28). 실물로 재 보니 **절반은 되고 절반은 안 된다.**

## 1. 지금 어디까지 되나 (.120 실측)

`wego-mink/sim_two_box_2_120/meta/` 를 직접 열었다:

```
info.json  piper_cameras.json  piper_scene.json  stats.json  tasks.parquet  episodes/
```

`piper_scene.json` 에 물체가 **통째로** 있다 — id·라벨·모양·위치·크기·색·질량·마찰·
solref·condim. v0.5.7 부터 **탑뷰 높이**(`cameras.top.z`)도 같이 실린다. 허브에도 따라간다:
LeRobot `push_to_hub` 가 `upload_folder(ignore_patterns=["images/"])` 라 `meta/` 는 통째로 올라간다.

체크포인트(`outputs/train/2026-09-23/06-56-41_act/checkpoints/020000/pretrained_model/`)는 다르다:

```
config.json  model.safetensors  train_config.json  policy_*.json/safetensors
```

`train_config.json` 이 아는 것은 **`dataset.repo_id` 문자열 하나**다. 세계 이야기는 없다.

| 질문 | 답 |
|---|---|
| 데이터셋에 환경 구성이 들어가나 | 프리미티브 물체 **☑** · ~~메시~~(껐다) · 바탕 세계 버전 **✗** |
| 가중치까지 가나 | **✗** — 데이터셋 이름만 |
| 남이 받아 **학습**을 돌릴 수 있나 | **☑** — 학습은 프레임만 쓴다. 세계를 다시 지을 필요가 없다 |
| 남이 받아 **추론**을 돌릴 수 있나 | 실기면 ☑. **시뮬에서 재현하려면** §2 의 셋에 걸린다 |

## 2. 빈 곳 셋

### 2.1 ~~메시가 안 실린다~~ → **메시를 껐다** (2026-09-28 해결)

`shape: "mesh"` 물체는 `asset: "<sha256 앞 16자>"` 로 **가리키기만** 했다. 파일은 게이트웨이의
`config/sim_assets/` 에 있고 데이터셋에는 없어서, 스캔한 물건이 든 가상환경으로 모은 데이터셋은
다른 기계에서 다시 지을 수 없었다.

**메시 가져오기를 끄는 것으로 닫았다** (`scene_spec.MESH_ENABLED = False`, 사용자 결정:
"전문툴도 아닌데 무리수가 많다"). 끄는 쪽이 맞는 이유: 메시는 모델링 도구의 일이고, 쓰려면
단위·원점·볼록껍질·닫힘 여부를 사람이 다 알아야 한다 — 우리가 대신 판정해 주는 만큼 **틀릴
자리**가 늘어난다. 실측으로도 **한 번도 안 쓰였다**(.120: 자산 0 · 메시 가상환경 0 · 그런
데이터셋 0).

⚠ 되살리는 날 이 구멍도 같이 돌아온다 — 그때는 §3-C 가 함께 와야 한다.

### 2.2 스키마·세계 버전이 안 적힌다

- `validate()` 가 채우는 `version`(스키마) 을 `sidecar()` 가 **안 싣는다**. 실제 파일이
  `{"id", "name", "objects"}` 로 시작한다 — 포맷을 바꾸는 날 읽는 쪽이 구분할 수 없다.
- 팔·테이블·조명·카메라 fovy 는 `piper_scene.xml`(wheel 안)에 있는데 **어느 판인지 안 적힌다.**
  ⚠ 이건 가상의 걱정이 아니다: v0.5.1 이 탑뷰를 0.9 → 0.6 으로 옮겼고(큐브 21 → 33px),
  그때 모은 데이터와 그 뒤 데이터는 **같은 세계가 아닌데 파일상으로는 구분되지 않는다.**

### 2.3 가중치는 데이터셋 이름만 안다

받은 사람은 `repo_id` 를 따라가야 세계를 알 수 있고, 그 데이터셋이 허브에 없거나 이름이
바뀌었으면 **영영 모른다.** 정책이 무엇을 보고 배웠는지는 그 정책을 **평가**할 때 필요한
정보다 — 화각이 다른 세계에 올려 놓고 "성능이 안 나온다"고 판단하게 된다.

## 3. 무엇을 고치나 — 셋은 **독립이다**

값어치 대비 비용 순서. 하나만 해도 이득이 남는다.

### A. 사이드카에 **버전 둘** (제일 싸다)

```json
{ "spec_version": 1,
  "sim": { "package": "0.5.8", "base_sha": "9f2c…" },
  "id": "…", "name": "…", "cameras": {…}, "objects": [ … ] }
```

- `base_sha` 는 **바탕 XML 의 내용 해시**다. 버전 문자열보다 정직하다 — 릴리스 번호가
  안 바뀌어도 그 파일이 바뀌면 다른 세계이고, 해시는 그걸 그대로 말한다.
- ⚠ **소급은 안 된다.** 이미 모은 데이터에는 못 넣는다. 읽는 쪽 규칙: 키가 없으면
  "v0.5.7 이전" — 그 이상은 알 수 없고, **모른다고 말하는 것**이 틀린 값을 지어내는 것보다 낫다.

### B. 학습이 **장면을 물려받는다**

학습 **시작** 때 데이터셋의 `meta/piper_scene.json` 을 `<output_dir>/piper_scene.json` 으로
복사한다. 이미 그 자리에서 `notes_sidecar.write_notes(output_dir, kind="model", …)` 를 부르고
있으므로 붙는 자리가 이미 있다.

- ⚠ **시작 때** 복사하는 이유: 데이터셋이 나중에 지워지거나 이름이 바뀌어도 가중치가 자기
  세계를 안다. 끝날 때 하면 그 사이에 사라진 데이터셋을 못 따라간다.
- run 루트에 두는 것은 `piper_notes.json` 과 같은 규칙이다 — 체크포인트에 자기 것이 없으면
  run 의 것을 물려받는다(`model_scanner` 가 이미 그렇게 읽는다).
- ⚠ 실기 데이터셋이면 **아무것도 안 쓴다.** 없는 것이 정상이고, 빈 파일은 "시뮬인데 기록이
  없다"와 구분이 안 된다.

### ~~C. 메시 동봉~~ — **안 한다** (메시를 껐다)

메시가 없으면 동봉할 것이 없다. 되살리는 날 이 자리로 돌아온다: 참조된 자산만
`meta/piper_assets/<asset_id>.<ext>` 로 복사(자산 id 가 내용 해시라 받는 쪽에서 검증까지 된다),
개당 32MB 상한이 데이터셋마다 붙는 비용을 그때 다시 잰다.

## 4. 하지 않는 것

- **데이터셋에서 세계를 자동 복원**("이 데이터셋의 가상환경 불러오기"). 사이드카가 자기설명이
  되면 그 버튼은 그 다음 이야기다 — 먼저 **적는 것**이 맞고, 읽는 것은 그 뒤에 값이 생긴다.
- **실기 데이터에 아무것도 추가하지 않는다.** 시뮬 사이드카가 없는 것이 실기의 정상이다.
- **LeRobot 파일(`info.json`·`train_config.json`)에 키를 끼우지 않는다.** 이 저장소의
  사이드카 관례가 있는 이유 그대로 — LeRobot 도구가 재작성할 때 보존을 보장하지 않는다.
- **옛 데이터 소급 기록.** 지어낼 수 없다(§3-A).

## 5. 테스트

| 무엇 | 어떻게 |
|---|---|
| 버전 둘이 실린다 | 사이드카에 `spec_version`·`sim.base_sha` 가 있고, XML 을 한 바이트 고치면 해시가 달라진다 |
| 옛 사이드카를 읽어도 안 죽는다 | 키 없는 옛 파일 → "모름"으로 읽고 예외 없음 |
| 학습이 장면을 물려받는다 | 시뮬 데이터셋으로 시작 → `output_dir/piper_scene.json` 이 데이터셋 것과 **같은 내용** |
| 실기 학습은 빈 파일을 안 남긴다 | 사이드카 없는 데이터셋 → 파일 자체가 없다 |
| 메시가 꺼져 있다 | 명세·API·화면 셋 다 (`test_sim_mesh_assets.py`) |

## 6. 순서

1. **A** — 사이드카에 버전 둘. 오늘 모으는 데이터부터 기록이 남기 시작한다(소급 불가라
   **빨리 넣을수록 이득**이다).
2. **B** — 학습이 장면을 물려받는다. 붙는 자리가 이미 있어 작다.
3. ~~**C**~~ — 메시를 꺼서 사라졌다.

⚠ 1 을 2 보다 먼저 하는 이유는 **가중치가 물려받는 내용이 버전을 포함해야** 하기 때문이다.
순서가 뒤집히면 버전 없는 사본이 체크포인트에 박제된다.
