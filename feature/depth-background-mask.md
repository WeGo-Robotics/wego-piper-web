# 깊이로 배경 지우기

정책이 배경을 안 보게 한다. 작업대를 옮기거나 뒤로 사람이 지나가도 같은 관측이
되게 하는 것이 목적이다.

---

## 1. 무엇을 지우나 — **컬러**를 지운다

셋 중 하나를 고르는 일이었다:

| 안 | 하는 일 | 판단 |
|---|---|---|
| **컬러를 깊이로 마스킹** | 정책이 보는 RGB 에서 배경을 검게 | ☑ **이걸 한다** |
| 깊이 스트림만 | `far` 밖을 무효로 표시 | 정책은 여전히 컬러로 배경을 본다 |
| YOLO 전처리 | 검출 전에 지워 오검출을 줄임 | 비전 서비스 쪽 일, 데이터셋과 무관 |

목적이 "정책이 배경에 안 물들게"이므로 **정책이 실제로 보는 영상**을 손대야 한다.

## 2. 경계는 `far_mm` 하나다

깊이 인코딩 창의 `far_mm` 을 그대로 쓴다. 창을 따로 두면 사람이 둘을 맞춰야 하고,
어긋나면 "깊이에는 보이는데 컬러에서는 지워진" 상태가 조용히 생긴다.

**`near` 는 안 자른다.** 배경은 **뒤에 있는 것**이다. 카메라에 아주 가까운 것을
지우면 집으려는 물체가 손 앞에 왔을 때 사라진다 — 정확히 필요한 순간에.

## 3. 깊이를 못 읽은 픽셀은 **남긴다**

⚠ 이게 이 기능에서 가장 중요한 결정이다.

실측: **D405 는 프레임의 42% 에서 깊이를 못 읽는다**(범위 밖·무늬 없는 면·반사).
"깊이가 없거나 멀면 배경"으로 만들면 **물체 한가운데가 숭숭 뚫린다.**

모르면 남긴다 — 배경이 덜 잘릴 뿐이지만, 반대로 틀리면 정책이 봐야 할 것을 지운다.
깊이의 `INVALID` 규칙(`depth.py`)과 방향이 같다: **모르는 것을 안전한 쪽으로 민다.**
거기서는 "가장 멂"이 안전이고 여기서는 "남긴다"가 안전이다.

> 구멍을 메운 뒤 판정하는 안(hole filling)은 더 깔끔하지만, 메운 값은 추측이라
> 틀릴 수 있고 비용이 붙는다. 남기는 쪽으로 먼저 써 보고 판단한다.

## 4. 정렬 — 켰을 때만

깊이와 컬러는 다른 센서다. 겹치려면 `rs.align(rs.stream.color)` 가 필요하고,
그건 **프레임마다 재투영**이다. 그래서 마스킹을 켠 장치에서만 돈다.

⚠ **정렬한 깊이는 마스킹에만 쓴다. 발행하는 깊이는 원본 그대로다.**
정렬하면 시점과 해상도가 컬러 쪽으로 바뀌는데, 그걸 조용히 바꾸면 마스킹을 켠 것뿐인데
깊이 스트림의 뜻이 이동한다 — 예전 데이터셋과 안 맞게 된다.

모양이 안 맞으면(D435 컬러 640x480 / 깊이 848x480 처럼) **마스킹을 건너뛴다.**
어긋난 마스크는 안 하느니만 못하다 — 물체를 엉뚱한 데서 지운다.

## 5. 지워진 데이터인지 나중에 알 수 있어야 한다

⚠ **프레임만 봐서는 못 가린다** — 어두운 배경과 지워진 배경이 똑같이 검다.
그래서 사이드카(`meta/piper_cameras.json`)에 남긴다:

```jsonc
"top": { "id": "rs:…:color", "background_mask": { "enabled": true, "far_mm": 410 } }
```

같은 이유로 **녹화 중에는 못 바꾼다**(`require_idle`). 도중에 바꾸면 한 데이터셋에
배경이 있는 프레임과 없는 프레임이 섞이는데, 사이드카에는 값 하나만 남아 거짓이 된다.

## 6. 소유자는 rsd

`depth_encoding` 과 같은 자리다. 데몬이 소유하면 **녹화와 추론이 같은 처리를**
받는다 — wrapper 에 두면 둘이 갈라져 "녹화는 지워졌는데 추론은 아닌" 상태가 생긴다.

## 7. 아직 안 한 것

- **구멍 메우기** — §3
- **채우는 색 선택** — 지금은 검정 고정. 하드 엣지를 정책이 잡아먹는지 봐야 안다
- **컬러 카드에서 직접 켜기** — 지금은 같은 장치의 depth 설정 패널에 있다
  (경계를 공유하므로). 컬러 쪽에도 표시가 필요한지는 써 보고 판단
